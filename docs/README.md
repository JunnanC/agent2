## 当前实现与边界

- 后端是 `backend/` 下的 Django 项目；前端是 `student-web`、`teacher-web`、`admin-web` 三个独立 React 应用。
- 日常运行采用 Docker Compose；业务 API、受控文件下载和工作区网关共用门户入口。MySQL 存业务事实，Redis 支持缓存、队列和事件转发，MongoDB 存运行日志，MinIO 存受控对象。
- 当前代码包含课程选课、模板与发布、五语言 IDE、工作区快照、正式测试与成果提交、教师审核和受控 Agent。代码存在不等于目标环境已验收。
- 当前有五份浏览器测试文件；真实工作区场景和集成脚本均存在。仍有 11 个早期浏览器验收入口缺少它们指定的场景或 npm 命令，详见[脚本索引](开发指南/脚本索引.md)。
- 前端热更新脚本默认按 `.env` 选择的 Compose 配置和 `runtime` profile 启动标准后端；已有后端时使用 `frontend-dev-up.ps1 -SkipBackend`。
- 当前 Nginx 仅放行学生端 SSE，教师端和管理端事件流仍被入口拒绝；三端实时更新需要单独核对。
- Swarm 真实执行、生产 Registry 晋级、外部存储故障切换、HA、备份恢复和滚动回退仍需目标环境的独立验收；本地测试不能代替。

## 命名约定

- 文件、脚本、命令、测试、业务显示名称及文档标题直接按业务或功能命名，不再使用 `p01`、`p02`、`t10` 等阶段编号，不维护旧编号映射表。
- 脚本按 `scripts/dev/`、`scripts/verify/`、`scripts/deploy/` 分类，文件名使用小写单词和连字符；Python 模块和 Django 命令使用下划线。
- 过程目录使用 `YYYY-MM-DD-专项名称/`；项目文档按内容命名。已有数据库迁移、稳定查找键及协议版本需按兼容性要求迁移，不能机械替换。
- 历史命令和证据保留原始事实；执行命令时查当前脚本和配置。
