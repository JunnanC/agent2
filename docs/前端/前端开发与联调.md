| 位置 | 当前内容 |

## 二、本地启动

先按[根 README](../../README.md)启动 8080 后端入口。前端在 `frontend/` 安装依赖后运行对应应用的 Vite 开发服务器：

```powershell
cd frontend
npm ci --ignore-scripts
npm run dev:student   # 教师端 dev:teacher，管理端 dev:admin
```

开发端口以各应用 `vite.config.ts` 为准；管理端、教师端和学生端代理分别以对应门户 Host 转发。Vite 代理 `/api`、`/files`，后端目标由 `VITE_DEV_API_TARGET` 指定，默认 `http://127.0.0.1:8080`。修改源码由 Vite 热更新，部署构建仍由 Nginx 在 `:8080` 提供。

## 三、请求与权限

- 通过 `@edu/auth-client` 和 `@edu/api-client` 访问 `/api/v2`，Session 请求使用 `credentials: "include"`。首次写入前获取 `/auth/csrf`，写请求发送 `X-CSRFToken`。
- 业务重试复用幂等键；需要版本控制的修改携带当前资源版本。412 时保留用户输入，重新获取并解决冲突，不能静默覆盖。
- 页面资格和按钮状态辅助交互，后端仍负责授权。会话失效时清理查询缓存并跳转登录。
- 学生工作台查询聚合接口，不自行拼装隐藏测试或内部执行命令；工作区访问通过服务端下发的受控会话。
- 错误形状、分页与接口修改流程见[数据与接口](../架构设计/数据与接口.md)。

## 四、状态、工作台与 UI

- 服务端数据统一进入查询缓存；SSE 触发相应刷新。断线、游标失效或 resync 后重新查询 REST，不能只根据事件修改业务事实。
- 当前 Nginx 只放行学生端 SSE；教师端、管理端事件流被入口配置拒绝，不能把共享客户端存在写成三端实时更新已打通。
- 学生答题页位于 `/experiments/:taskId/assessment`，采用全屏布局；代码入口是[assessment.tsx](../../frontend/apps/student-web/src/pages/assessment.tsx)。CodeMirror 编辑和草稿保存不依赖容器会话。
- 保存、恢复、语言切换、运行测试和完成提交均依据后端状态启用。运行中、失败和版本冲突需要明确反馈，保留尚未保存的编辑。
- 优先复用 `@edu/ui` 及[共享样式](../../frontend/packages/ui/src/styles.css)。2026-11-24 选定的[教师 B 版](./教师B版基准/02-agenda.html#home)作为本轮教学日程与教学班界面的视觉基准，其他历史原型仅供追溯。正式应用沿用各端现有业务路由与接口。
- 修改页面时检查加载、空态、错误、无权限、窄屏与键盘操作；不要另建一套重复组件或状态映射。

在 `frontend/` 执行：

```powershell

npx tsc -p e2e/tsconfig.json --noEmit
```

当前六份浏览器用例为 `admin-console`、`admin-smoke`、`teacher-smoke`、`assessment`、`assessment-teacher` 和 `analytics-notifications`。执行配置见 [playwright.config.ts](../../frontend/playwright.config.ts)。

浏览器测试需要可访问服务和对应数据；部分冒烟用例在缺少账号环境变量时会跳过。真实工作区流程需要任务、登录凭据及运行时，按[轻量答题验收](../开发指南/轻量答题验收.md)执行。用例存在、类型检查通过或部分跳过都不等于完整业务验收。

## 六、构建与契约更新

三个应用分别构建到 `frontend/dist/student-web`、`teacher-web`、`admin-web`，部署时由 [Nginx 镜像](../../infrastructure/nginx/Dockerfile)统一提供。

后端接口修改后，从仓库根目录运行 `./scripts/dev/export-openapi.ps1`，再检查 API 客户端和页面调用。不要手改生成的 `schema.d.ts`，也不单独维护一份手写全量 API 目录。

## 七、共享资源类型

[types.ts](../../frontend/packages/api-client/src/types.ts)表达前端业务资源类型，[生成类型](../../frontend/packages/api-client/src/generated/schema.d.ts)来自 OpenAPI；两者都需要与当前 serializer 保持一致。资源标识、任务与审核状态、运行证据和工具链字段以当前实现为准，页面不能自行扩展后端枚举或假定所有列表响应相同。


## 教师端开发计划与交付记录（2026-11-06）

该阶段依据 prototypes/teacher，保留当时的 React 技术栈和业务接口，仅修改前端。以下记录当时交付的侧栏、页签与业务流程。本轮教师端首页及教学班布局按上方 B 版计划实施。

1. 左侧导航为教学概览、我的课程、通知；收起按钮放产品名称右侧，记忆折叠状态。
2. 我的课程使用搜索与卡片；课程内部统一上下文及概况、成员申请、实验进度、设计、发布、分析页签。
3. 新建模板后进入编辑；配置发布携带模板 ID 并打开真实发布表单，沿用创建、预检与发布接口。
4. 发布内进入评审，按 publication_id 隔离；全量分页读取后筛选，全选覆盖全部筛选结果。现有 AI 接口对整个发布评分，采纳与最终教师确认分开，逐份反馈部分失败。
5. 教学分析增加实验筛选，全量已分配任务作为分母，未提交计 0；待教师确认暂计 0 并标注。真实成绩从评审详情的教师决定读取。
6. 重做公式 max(first, min(second, 60)) 有单测。当前接口缺少关联与去重，普通发布统计不冒充已支持重做；安排重做入口明确待接入。
7. 课程内验证工作台与学生个人汇总提供页面及接口缺口说明；后端交付教师会话、报告接口和稳定学生标识查询后继续联调。

验证：教师端类型检查、生产构建、5 个测试文件共 11 项通过。真实环境登录、发布、AI 服务与教师工作台未完成联调，不以 HTML 演示代替正式功能验收。后端分析报告与实施任务见开发指南/后端开发.md。

## 课程筛选与补做成绩契约（2026-11-06）

以下为上述教师端交付之后新增的实现：

- `GET /api/v2/tasks` 使用 `course_id` 筛选课程；兼容旧 `course`，两者非空且不同时返回 400。
- `POST /api/v2/teaching/courses/{course_id}/experiments/{publication_id}/retakes` 接收 `selected_enrollment_ids`、`window_start` 和 `window_end`，要求 `Idempotency-Key`。使用选课记录 ID，与已有普通发布契约保持一致；服务端验证当前有效选课和同一学生的原实验任务。
- 空名单不创建批次；每个原实验任务只能关联一次补做；只能对已发布或已关闭的普通实验创建补做。开放时间必须在未来且早于截止时间。同步创建返回 201，异步分配返回 202，原任务和原发布保留。
- 发布响应增加 `retake_of_publication_id`。教师任务列表增加 `score`（服务端有效成绩）、`retake_of_task_id`、`has_retake` 和 `retake_task_id`。异步分配未完成时 `has_retake` 已为 true，`retake_task_id` 可为空。
- 评分细项保留原始分数；补做确认决定和关联记录中的登记分均封顶为 60。原实验有效成绩取原成绩与补做登记分的较高值。未评分的补做不替代原成绩；均未评分时 score 为空，页面汇总按 0 计。
- 教师成绩页、课程进度成绩汇总和学生学习历史按原实验只计一次；操作任务列表仍保留补做任务。学生评审结果增加 `effective_score`，各轮历史评审决定保持原记录。
- 数据库新增发布来源字段及 `ExperimentRetakeLink` 关联模型，迁移为 experiments `0004`、`0005`；上线代码前需要在目标数据库完成迁移。当前阶段验证使用项目 SQLite 测试设置，不代表实际 MySQL 或线上浏览器总体验收已完成。
