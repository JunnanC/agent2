# 教师端 B 版复刻与三端前端开发计划

## 给开发模型的起始指令

> 在本仓库实施教师端 B 版。先打开本计划旁的 `教师B版基准/02-agenda.html#home`，操作日程、周课表和教学班，再阅读其完整 CSS 和脚本。以该文件的实际渲染作为教师端的视觉和交互基准。把结构和样式移植到现有 React 应用，固定数据先做截图对比，再连接现有接口。学生端依照同一套配色和按日期、课程进入任务的工作方式验收，管理端的改动限定为颜色值。检查当前分支已实现的部分，仅补齐差异。执行下文验收，报告所用数据、各视口截图、差异和测试结果。

交给另一个模型时，一并提供仓库、本文和同级的整个 [教师B版基准](./教师B版基准/) 文件夹。文件夹内的 [可运行 HTML](./教师B版基准/02-agenda.html#home) 含完整样式、SVG 路径、样例数据及交互，可离线打开。原件位于仓库工作区的 `prototypes/teacher/design-options/02-agenda.html`。基准图分别是 [桌面日程 1440 × 900](./教师B版基准/home-1440.png)、[手机日程 390 × 844](./教师B版基准/home-390.png)、[教学班实验列表 1440 × 900](./教师B版基准/class-1440.png)。交接环境若出现字体差异，在同一机器上同时渲染 HTML 和应用，再比较两张图。

### 桌面首页

1. 顶栏使用 `.top > .wrap.top-inner`，行高由 `min-height:58px` 控制，下方 1px 分隔线。左侧书本标记和“教学实验平台”，右侧铃铛、32px 圆形头像和姓名。主内容与品牌同一左边缘。顶栏下依次放 `.page-heading`、`.journal` 和夹具页脚。
2. `.wrap` 有效宽度为 `min(1176px, 100% - 64px)`，水平居中。1440px 宽时左边缘 x=132px。标题区上下内距 32 / 26px，右端顺序为学期选择、实验环境、导入课表。主操作仅用于导入。
3. 日程本是一整块带 1px 边框的容器。桌面网格 `minmax(244px,26%) minmax(0,1fr)`。左页 25px 22px 22px 内距，月历周一起始，七列，日期按钮 31 × 31px，选中日为酒红圆形。下接“我的教学班”，列表行最小高 65px。右页内距 `22px clamp(22px,3.2vw,48px) 27px`。
4. 右页第一行左侧是日期大字、星期和年月，右侧是日程 / 周课表切换器。粗横线下放当日课程、周切换和本周按钮。课时行网格为 `80px minmax(0,1fr) auto`，间距 16px，内距 19px 18px。下隔 24px 进入教学待办，每项左侧为动作和上下文、右侧为数量。1440px 首屏可用坐标核对：日程本左上约 (132,161)，左右页分界 x≈438，右页内容起点 x≈484，课程行上边 y≈350。

## 3. 教师端实现顺序与路由

1. **公共框架。** 从 `frontend/apps/teacher-web/src/app/guards.tsx` 和 `app/course-layout.tsx` 接入新工作区。保留 Session、门户校验、通知查询、退出登录、Outlet 和直接访问已有路由的能力。已登录首页只渲染一个顶栏和一个标题区。头像菜单沿用现有退出功能。匹配的图标可复用共享组件，书本等形状与参考不一致时使用原型 SVG。
2. **教学日程。** 在 `src/pages/home.tsx` 将现有课表、班级索引、待批报告、入班申请组合进同一个日程本。把原有完成率、趋势、课程汇总放在已有分析或课程入口中。沿用现有 `timetableApi.teaching`、`teachingApi` 和查询键，逐实验的报告状态取自 `assessmentPartsApi.reports` 或等价的真实报告汇总。已有教学班管理和新建课程入口从班级索引或其空态进入。铃铛在夹具中打开“通知中心”弹窗，内有“入班申请 · 数据结构 01 班”和“查看入班申请”，点击后关闭弹窗并到达该班名单。生产端从实际通知进入对应事项，同时保留现有 `/notifications` 入口。
3. **日期与学期。** 参照 `handleAction` 与学期 change 事件维护每学期的周序，以及跨学期保留的星期、日 / 周视图。选日期同时更新周序、星期和右页，重置月偏移并切回日程；翻月只改变小月历；切周保留星期并重置月偏移。仅当前学期显示“本周”，已经在本周时禁用；首周、末周分别禁用后退、前进。换学期恢复该学期上次查看的周，首次进入取学期默认周。周课表的“今天”高亮依据真实今天，选中月历日期用另一选中状态。应用继续支持 URL 的 `term` 参数和浏览器返回。按学期筛课程，生产数据另按周次范围和单双周筛授课，按节次排序。同一时段多节课全部列出。夹具周课表固定周一至周五、五个节次段，生产数据若有周末或其他节次再扩展。
4. **日历依赖。** `frontend/packages/api-client/src/types.ts` 的 `TimetableTerm` 当前只含 ID、代码、名称；`TimetableSchedule` 含节次与单双周，未提供每节上课钟点。优先核查该门户已授权的数据源，以学校时区、学期起止、教学周起算规则及学校节次表计算日期和钟点。缺少学期边界时展示已知星期、节次和周次条件，日期换算控件显示不可用原因；缺少钟点时显示节次。正式精确日历依赖真实校历，需明确记录缺失字段。夹具使用原型秋季 16 周及示例钟点。
5. **教学班详情。** `app/course-layout.tsx` 承载班级返回、标题、学期/人数/实验数、课程码及四个标签。表格 `th/td` 内距 13px 16px，头部最小高 68px；标签高至少 45px，当前项底线 2px。源码函数 `classPage`、`experiments`、`roster`、`timetable`、`grades`、`review` 给出每个区域的顺序、文案、禁用状态和空态。

| 原型状态 | 接入现有教师路由或能力 |
| --- | --- |
| `#home`，月历、节次、教学班、待办 | `/`；点击课时与教学班进入对应 `/courses/:courseId`；待办直达该班入班申请或指定实验评审 |
| `#class/:id/experiments` | `/courses/:courseId` 的首个标签，表中列实验名称、截止、状态、报告提交、操作；新建实验接 `LabDesignDialog`；模板编辑、发布流程保留已有深链 |
| `#class/:id/roster` | `/courses/:courseId/enrollments`，上方申请、下方名单；接入批准、导入、邀请。学生进度仍可访问 `/courses/:courseId/students`，个人详情为 `/courses/:courseId/students/:studentId` |
| `#class/:id/schedule` | 在 `/courses/:courseId` 增加可深链的 `?tab=schedule` 标签，使用 `timetableApi.teachingCourse(courseId)`，实例只显示当前班 |
| `#class/:id/grades` | `/courses/:courseId/analytics` 复用 `ReleasedGradeBoard` 的已发布成绩查询和 CSV 导出；夹具核对已发布实验、参与总评、平均分、挂科率及分项反馈。原有 `GradeAnalysis` 的任务、补做继续可达 |
| `#class/:id/review-:labId` | `/courses/:courseId/publishing/:publicationId/reviews?tab=reports`；现有评审路由用此参数进入实验报告。实验列表标签维持选中，复用 `AssessmentReportReview`、`LabGradeRelease` 等逐份批阅、发布和发布后只读能力，核对批量 AI 批阅的支持范围 |

6. **二级操作。** 将 `TimetableImport` 放入页头导入流程，沿用上传、字段映射、预检、行级错误与最终状态。首页“实验环境”触发 `LabEnvironments`，当前接口要求 courseId，多个班时由教师在弹层内选择，禁止默认写入首个班。课程码显示和复制应接入可恢复的有效邀请码及真实权限；审批、评分、发布和导出均沿用真实服务端资格及状态。弹窗保留原型的 620px 宽度上限、88vh 高度上限、标题关闭键、遮罩、键盘退出及焦点返回。弹窗内任务提交期间避免重复提交，失败后保留输入。
7. **安置原有功能。** 课程公告、章节资料、学生进度、模板与发布设置仍需有可达入口。把资料与公告、模板管理等次级操作收到对应班级的菜单/详情；核对旧网址可直接打开、刷新、返回。课程详情内的每个入口使用当下真实 courseId 或 publicationId。

**演示流程的复刻检查。** 教学班和首页通过 hash 切换时滚动回顶部，班级四个标签从左到右是“实验列表、学生名单、班级课表、成绩分析”。“栈与队列”样例的待办直达 `#class/ds01/review-lab2`，三份报告评分就绪后待办改为“发布实验成绩”，确认发布后该待办消失。名单 / 课表导入演示依次打开载入示例、核对表头映射、导入预检，以“完成预览”关闭；正式提交沿用项目导入任务。成绩导出对话框默认勾选全部已发布实验，全部取消时提示至少选一个。复刻这些状态时，对外示例写入、生成题目、AI 批阅与环境测试的结果仅用于夹具，正式流使用现有服务的结果。

## 4. 学生端融合，管理端统一颜色

| 角色 / 位置 | 用户应能完成的动作 | 验收 |
| --- | --- | --- |
| 学生首页 `/` | 在同一工作区查看学期课程、按日期查看课表及实验待办，从一个课时进入课程或从一个任务进入实验 | 桌面共享日程本的侧栏和主内容区，手机主内容优先；课程名、截止、提交状态、最近评分取自学生已授权数据；保留加入课程、通知、个人资料入口 |
| 学生课程 `/courses/:courseId` | 从本课程切到实验、章节资料、公告 / 日历、讨论，再返回当前课程 | 通过实际 courseId 关联实体，保留章节和问答深链以及离课权限校验；课程码加入仍走 `/courses/join` |
| 学生实验 `/experiments/:taskId` | 从课程或待办进入实验详情、答题、交卷，再回到已打开的任务 | `/experiments/:taskId/assessment` 保留独立全屏、草稿、运行/提交和已发布结果；真实空态、错误重试、未入班、中止均可辨识 |
| 管理端登录及控制台 | 按原路径登录、切换栏目、筛选表格、打开弹窗、执行已有动作 | 限定 admin-web 颜色声明，按第 2 节映射画布、表面、文字、线条、主色、悬停与状态色。验证字体、行高、边距、圆角、阴影几何、响应式布局、图标路径、文案、DOM、事件和业务路由与改色前一致 |

两端复用同一语义色映射。课程区分色和成功、警告、错误色承担独立含义。管理端既有渐变、边框、填充、图表与阴影仅替换其中的颜色，保留角度、透明层次和几何值。先查看 `frontend/apps/admin-web/src/console/console.css`、登录页与共享样式的导入顺序，只在管理端作用域覆盖共享控件。学生端在 `frontend/apps/student-web/src/app`、`pages`、`components` 和角色专属样式实施，避免跨角色修改全局 CSS。

## 5. 验收与交付证据

1. **固定条件。** 同一 Chromium 版本、系统、字体、语言 zh-CN、时区 Asia/Shanghai、DPR=1、缩放 100%，同一日期与数据。等待字体、查询及布局稳定，从页面顶端截取视口。分别截原型和应用，保存基准、结果、差异图。直接复制原型截图用作背景无法通过交互验收。
2. **三张必对图。** 按本文开头的三个文件名匹配视图和窗口大小。对截图做半透明叠图和逐像素差分；同机、同字体、同夹具以零可见差异为目标。用 `getBoundingClientRect()` 对照顶栏、容器、侧栏、日期、切换器、教学班行与按钮的位置/大小，四舍五入至 CSS 像素应一致。纯色区域用取色器比对十六进制值，文本比较字族、字号、字重、行高、折行和基线。将任何残差定位到区域并说明，不能用全屏差异百分比吞掉局部错位。
3. **扩展断面。** 在 768px 宽检查双栏和周表内部滚动；对 1050、870、680、640px 的边界及其相邻宽度检查切换点。另截周视图、名单、班级课表、成绩、评审、典型弹窗、无排课日期。表格列、图例和指标在桌面与手机均可访问，页面无意外横向滚动。
4. **教师操作串测。** 月历选周末 → 当日无课 → 上一周 / 下一周 / 本周 → 周课表 → 选教学班 → 复制课程码 → 审核申请 → 返回首页核对人数 → 打开实验评审 → 保存评分 / 批注 → 满足条件后确认发布 → 成绩只读 → 导出。另测学期切换、导入失败及重试、环境测试和通知入口。写操作使用隔离的测试数据。验证 Tab、Enter、Escape、可见焦点，及 `aria-pressed`、`aria-current`、禁用状态和反馈文本。
5. **两端回归。** 学生端完成“日程 → 课程 → 章节 / 实验 → 全屏答题 → 返回”，验证日期/学期切换、无课程、无待办、超期、无权限与错误状态。管理端改前改后在同一账号、数据、视口采集页面，比较结构、文字、焦点顺序及控件边界；检查源码差异中的每条 CSS 或 SVG 变更仅涉及颜色，回归现有管理冒烟用例。
6. **仓库命令。** 在 `frontend/` 执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。按 [前端开发与联调](./前端开发与联调.md) 配置测试服务和账号，运行相应 Playwright 项目与用例。分别记录通过、失败、跳过，以及使用静态夹具还是实际后端。交付修改文件、可复查的截图对照及遗留业务依赖。

### 教师首页的第一轮验收

把原型和 React 首页并排打开，固定 1440 × 900、DPR 1、同一套本机字体，清空页面滚动位置。先量品牌与主标题的左边缘，再量日程本左右分栏，最后量日期基线、课程行与待办行。若整页向内偏移，先查应用外壳是否额外加了一层容器；若只有文字或按钮下移，检查继承的行高、默认段落外距及字体回退。桌面通过后切到 390 × 844，此时应能直接点七日条中的另一天，并看到课程和选中态一起更新。

交接时对每张图记录视口、路由、学期、选中日期、截图文件和剩余差异。首页通过后，将同一批布局组件用于班级页。真实接口返回的姓名、人数、实验数和待办条数均允许随数据变化；固定夹具用于判断排版是否偏离。

### 学生日期和课表的边界

学生课表返回星期、起止节次、教学周范围及单双周。选择具体日期时，任务按开放与截止日期计算。若响应缺少校历，课程区显示对应星期的常规排课，并在课程行保留教学周和单双周条件。选往期学期时，课程索引和所属课程待办一起切换。没有数据的学期显示空态。待校历和作息时间表接入后，再验收某个具体日期的实际课程和上课钟点。

### 管理端回归记录

本次以相同的隔离接口数据对比改色前后构建，检查桌面概览和学生管理、平板课程与班级、手机概览和登录。上述五组页面的可见元素数量与边界一致；概览页的“数据更新时间”随请求时间变化。现有管理端浏览器用例仍按旧导航文字“课程与班级”查找按钮，改色前就会在该步骤超时。复测时用当前导航名“课程”进入，以页面标题“课程与班级”判定到达。
