# 三门户域名入口与 Cookie 隔离

同一 IP 的 `/__portal/student`、`/__portal/teacher`、`/__portal/admin` 如果通过 `portal` Cookie 切换站点，会使同一浏览器所有标签页一起切换。三端还共享同名 `sessionid`：后登录覆盖先登录，旧页面请求遇到 `SESSION_PORTAL_MISMATCH` 时还会删除共享会话。前端清缓存、修改 Cookie 端口、单独改 session Cookie 名均不能同时解决页面路由和认证串用。

修复遵循现有架构：三个独立 hostname，服务端 session 仍绑定 portal，Cookie 保持 host-only。宿主机入口按 Host 固定转发至 `student.localhost`、`teacher.localhost`、`admin.localhost`，内部 Nginx 和 Kong 不变。权限拒绝和跨门户 session 拒绝逻辑不变。

## 无自有域名时的临时入口

`infrastructure/nginx/host-portals.conf` 为当前 `121.43.117.116` 提供可审阅的宿主机配置，使用自动解析 IP 的临时 DNS 名称，无须购买或配置自有 DNS：

| 门户 | 临时 HTTP 地址 | 内部 Host |
| --- | --- | --- |
| 学生 | `http://student.121.43.117.116.sslip.io` | `student.localhost` |
| 教师 | `http://teacher.121.43.117.116.sslip.io` | `teacher.localhost` |
| 管理 | `http://admin.121.43.117.116.sslip.io` | `admin.localhost` |

这是现有 HTTP 测试环境的入口修复。正式 HTTPS 上线时替换为自有域名、配置对应证书，并保持生产 Secure Cookie 设置。三个旧 IP 书签仅返回 302 到相应域名，不再写 `portal` Cookie；共享 IP 下其他旧 API/业务路径返回 410，避免继续在共享源上认证。旧会话不会迁移，首次访问新域名需要重新登录。

## 应用到现有服务器

1. 先查看 `nginx -T`，找到旧的 IP server 和 `$cookie_portal` 路由。备份该站点配置。用新配置替换对应的 HTTP 入口，把文件包含在宿主机 `http {}` 中。不要把完整宿主机配置覆盖进容器，也不要同时保留两个匹配相同域名/IP 的 server。已有 443 站点需使用相同的 Host 映射，不能继续通过 Cookie 选择门户。
2. 保留现有业务配置，只追加三端 HTTP 来源到 Django `DJANGO_TRUSTED_ORIGINS`。为后续 HTTPS/CD 预检也追加对应 HTTPS 来源。更新服务器私有 `.env` 中 `STUDENT_HOST`、`TEACHER_HOST`、`ADMIN_HOST` 为表中三个公共 hostname（不带协议、端口或路径）。
3. Compose 的现有 `WORKSPACE_ALLOWED_ORIGINS` 是固定的本地来源。服务器 override 必须显式把 `django` 和 `workspace-gateway` 的该变量覆盖为包含 `http://student.121.43.117.116.sslip.io` 的列表，并保留仍需使用的来源。后续 HTTPS 同样追加 HTTPS 学生来源。不要只改 `.env` 而忽略已解析的 Compose 值。
4. 核对 `docker compose ... config` 中 Django 的 `DJANGO_TRUSTED_ORIGINS` 包含六个来源，两个工作区服务的 `WORKSPACE_ALLOWED_ORIGINS` 包含学生入口。内部 `DJANGO_ALLOWED_HOSTS` 继续允许三端 `.localhost`，Kong 继续使用仓库中的固定映射。
5. 先运行 `nginx -t`；通过后按原有部署方式更新受影响的 Django/工作区服务，再 reload 宿主机 Nginx。此变更不需要数据库迁移，也不需要重建前端。不要重启或重建数据服务。
6. 运行 `python3 scripts/cd/check-portal-entry.py /etc/agent2-cd/.env`，从域名核对三个实际健康响应的 portal。该检查不依赖本机 DNS、不接受 302，并主动附带错误的旧 selector Cookie 验证它不能覆盖 Host。
7. 用同一浏览器依次验证六种三端登录顺序，每一步刷新已登录标签页，核对各端 `/api/v2/me` 的账号和 portal。分别退出学生、教师、管理端，确认其余两端仍登录。检查旧 IP 三个书签跳到相应新域名，且不再设置 selector Cookie。

部署脚本不自动替换宿主机配置。必须先完成这次宿主机入口迁移；新冒烟检查会拒绝旧的 Cookie 路由，不能以返回了 HTML 就认定发布成功。回退时恢复备份的宿主机站点和本次追加前的私有环境配置，重新校验并 reload；回退入口也会恢复已知的串用问题。
