# 旧工作区配置清理交接

本轮范围仅限旧配置、模板与对应配置检查。业务代码、数据库结构、历史迁移及测试种子维持已提交版本；完整业务代码清退不在本轮继续执行。

## 开发侧已处理

- 先前提交已移除旧 IDE 页面、对外工作区路由、网关及常驻工作区部署服务。
- 删除无应用引用的旧网关 Cookie、Origin、内部鉴权、上游超时及授权服务地址配置。
- 移除 Compose／Swarm 对旧工作区存储 worker 的参数注入，以及环境模板中的无效参数。
- Swarm 模板的默认镜像统一为 stdio；不表示 Swarm 分布式判题已支持。
- 保留新代码快照需要的大小限制，以及内部存量代码仍读取的配置默认值，避免配置清理破坏共享能力。

## 测试侧

- 在独立环境验证纯选择、纯编程、混合实验的保存、运行、两份交卷、报告评分和结果公开。
- 核对账号、课程权限、附件、成绩统计、归档和重交的相关回归。
- 运行真实 Docker 多语言及隔离测试；单独验证真实 MySQL 并发，不能以 SQLite 代替。
- 本轮试验用的 `assessment-dev` 库曾执行未采纳的结构迁移，服务已停止；复用前重建该独立测试库，勿混用其旧结果。主项目数据库未执行这些迁移。

## 运维侧

- 部署前检查服务器实际 `.env`、Compose override、镜像版本、队列与旧服务状态；仓库模板清理不会自动修改线上配置。
- 按明确 Compose 项目与服务标签停用旧网关、旧存储 worker 和常驻工作区，先留备份再处理其队列与数据卷；不做全局 Docker 清理。
- 确认 stdio 镜像可用、Beat 正常调度、ClamAV 健康，并验证配额和资源回收。
- 主测试数据重建、旧容器／卷删除、生产容量与部署验收由运维按环境执行；本轮没有实际部署或清理这些资源。

本轮未采纳的代码清退草稿保存在本地忽略目录 `outputs/暂存_未采用的代码清退`，不纳入 Git，不作为已完成实现。
