## 当前镜像与工具链

真实工作区位于 [runtime/algorithm-workspace](../../runtime/algorithm-workspace/)，面向 Linux AMD64，提供 code-server 4.104.2 与 ttyd 1.7.7。工具链由 [toolchains.py](../../backend/apps/labtemplates/toolchains.py)冻结：

| 语言 | 当前版本 | 语言标准 |
| --- | --- | --- |
| C | GCC 12.2.0 | C17 |
| C++ | G++ 12.2.0 | C++20 |
| Java | OpenJDK 17.0.21 | 17 |
| Python | CPython 3.14.0 | 3 |
| Go | 1.25.1 | 1.25 |

模板可固定语言，或使用学生自选模式；允许语言和默认版本写入冻结策略。执行计划、工程入口和测试规则以模板版本与发布时的配置为准，不能使用宿主机环境代替。

依赖与构建来源分别在 [Dockerfile](../../runtime/algorithm-workspace/Dockerfile)、[requirements.lock](../../runtime/algorithm-workspace/requirements.lock)、[debug-extensions.lock.json](../../runtime/algorithm-workspace/debug-extensions.lock.json)。基础镜像、下载包与扩展有摘要或版本约束；系统传递依赖仍受构建时软件源影响，不宣称逐位可重复构建。

## 网关与容器边界

- 路由器监听 8080；code-server 和 ttyd 仅监听容器内回环地址。
- `/healthz` 提供健康探针，`/webide/` 提供 IDE，`/terminal/` 提供终端和 WebSocket。
- `/webide/edu-control/{status,save,reload}` 提供编辑器保存桥，检查未保存编辑并控制保存、重载。
- 当前真实镜像未提供 notebook、preview 能力；通用网关路由存在不表示镜像支持该能力。
- IDE 和终端上游请求要求 `X-Workspace-Upstream-Token`，令牌从挂载的 secret 读取；代理校验后移除传入密钥头。
- 工作区运行用户为 UID/GID 10001；工作文件位于任务专属 `/workspace` 卷，用户配置与缓存使用受控临时目录。
- 运行时应提供只读根、临时文件系统、能力裁剪、no-new-privileges、CPU/内存/PID/TTL 约束和内部网络；不对宿主机发布工作区端口，不向学生容器挂载 Docker Socket。

## 工程、快照与正式测试

教师上传的工程、公开数据和测试附件经扫描、归属和路径检查后使用。当前支持多文件工程和安全的相对嵌套入口；路径与归档限制见 [project_archive.py](../../backend/apps/core/project_archive.py)。

工作区存储任务通过专用队列执行保存、恢复与最终快照，见 [storage.py](../../backend/apps/workspaces/storage.py)。快照按摘要绑定到受控对象并记录状态，恢复不能绕过扫描及任务归属。Go 包装器把临时可执行文件和缓存放到 `/workspace/.cache`，快照排除生成缓存。

正式判题使用隔离的一次性执行环境，结果与任务、配置和快照绑定。语言切换或代码变化后需要新的有效测试证据；提交资格由后端计算。学生接口只暴露允许的公开示例和测试结果摘要，隐藏测试不返回完整输入、期望输出或内部命令。

教师自动复核使用提交时的快照语言和同一套编译/运行计划，校验成果归属及执行契约摘要，并使用冻结的比较器和数值容差。复核结果保留为审核证据，最终成绩仍由教师决定。

停止、完成和回收走业务生命周期，撤销会话并释放预留；卷、快照与成果按各自保留策略处理。不要用全局 Docker 清理代替任务回收。

## 构建与验证

从仓库根目录执行镜像专用门禁：

```powershell
./scripts/verify/workspace-image.ps1
# 使用已有镜像时：
./scripts/verify/workspace-image.ps1 -Image experimental-platform-workspace:local -SkipBuild
```

脚本验证隔离配置、语言运行与调试、命令覆盖，并用 `docker scout sbom` 生成 SPDX。默认证据位于 `evidence/workspace-image/`。构建需要访问固定下载来源，或提供经过大小、摘要、扩展 ID 和版本校验的 VSIX 缓存。

已有六个 `<id>.vsix` 文件时，可提供 BuildKit 上下文：

```powershell
docker buildx build --load --platform linux/amd64 --provenance=false --build-context "debug-vsix=C:/path/to/vsix" -t experimental-platform-workspace:local runtime/algorithm-workspace
```

镜像门禁不启动完整平台。浏览器保存桥检查在 [bridge-browser.cjs](../../runtime/algorithm-workspace/tests/bridge-browser.cjs)；完整学生旅程使用 [real-workspace-integration.ps1](../../scripts/verify/real-workspace-integration.ps1)，会校验快照、对象摘要、令牌边界并精确回收测试资源。
