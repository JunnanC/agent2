前端常规检查在 `frontend/` 执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。真实工作区可选 Docker Playwright 或已授权的 ego-browser 空间；`-UseRunningServices` 必须同时指定 `-ExistingTaskId`，该任务必须允许验收和回收。先阅读脚本参数，不在日常业务任务上直接试跑。

## 累计与专项门禁

`scripts/verify/*-static.ps1` 多数是历史累计门禁，可能执行整个后端、导出契约、检查前端及 Compose，不能按文件名推断只验证一个模块。

- 累计业务入口：`platform`、`core`、`accounts`、`courses`、`governance`、`templates`、`publications`、`provisioning`、`workspaces`、`reports`、`reviews`、`archives`、`agents`。
- 专项入口：`analytics-notifications-static.ps1`、`integrations-static.ps1`、`operations-static.ps1`、`workbench-static.ps1`。
- 仍有独立基础设施检查的集成入口：`core-integration.ps1`、`courses-integration.ps1`、`governance-integration.ps1`；会创建测试服务、写入或清空测试数据，先核对项目与参数。
- 脚本全集以 [verify 目录](../../scripts/verify/)为准；日常优先使用后端门禁、前端 npm 命令和工作区专用入口，避免重复运行多套累计门禁。
