# 轻量答题验收与测试种子

在独立测试库、对象存储桶和 Compose 项目运行，不清空日常开发数据。命令不创建账号、课程或镜像审批，也不修改已有学生答案。

## 准备

- 已发布的测试课程，已有教师和至少一名有效选课学生。
- 编程实验使用启用的 `DOCKER_LOCAL` 运行时、已扫描审批的 stdio 镜像和有效资源规格。
- 配置真实 Docker、对象存储和扫描服务，启动 Celery worker 与 Beat；`LOCAL_RUNTIME_MODE=REAL`。
- 仅设置 `APP_ENV=local`、`integration` 或 `test`；命令拒绝其他环境。

## 生成三类实验

在 backend 目录，使用当前环境的 Python：

```powershell
$env:APP_ENV = 'local'
python manage.py seed_assessment_e2e --course-id <课程ID> --run-id acceptance-20261112 --kind ALL --runtime-id <运行时ID> --image-id <镜像ID> --profile-id <规格ID> > ../outputs/assessment-fixtures.json
```

输出包含实验、任务和学生标识，无密码。相同课程与 run-id 重跑复用已有实验；已撤销或关闭的实验请使用新 run-id。纯选择题可用 `--kind CHOICE`，无需三个运行资源参数。编程与混合实验会执行真实参考解预检及工具链冒烟，失败时不发布。

种子包含单选、多选、五语言整数求和、两组隐藏测试；混合实验包含必填的十分制总报告。它依次调用正式题目、预检、量表和发布服务，不跳过权限或审批。

## 验收

仓库根目录验证五语言、多文件和隔离约束：

```powershell
python scripts/verify/assessment-runtime-smoke.py --image experimental-platform-stdio:local
```

在 frontend 目录运行三类学生旅程（需要 worker、Beat 和门户运行）：

```powershell
$env:ASSESSMENT_E2E_MANIFEST = 'E:\Agent\outputs\assessment-fixtures.json'
$env:E2E_STUDENT_URL = 'http://student.localhost:5173'
$env:E2E_STUDENT_PASSWORD = '<测试学生密码>'
npm exec -- playwright test e2e/assessment.spec.ts --project=student-web
```

未提供 manifest 或学生密码时浏览器用例会跳过，跳过不能算验收通过。学生密码仅从环境变量读取。多名学生时可设置 `E2E_STUDENT_ID` 为 manifest 中的学生邮箱。

数据库行锁并发验证使用真实 MySQL：`python manage.py test apps.experiments.tests.test_assessment_concurrency --noinput`。SQLite 跳过此项，不能替代 MySQL 结果。
