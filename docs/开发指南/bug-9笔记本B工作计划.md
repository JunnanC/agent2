# Bug-9 笔记本 B 工作计划

基线：`origin/main` 的 `0f113794bbaa7980cf5a5020e3329b709838e65e`。工作分支：`codex/bug-9-teacher-workflows`。

笔记本 B 负责教师门户工作流、教师通知和教师名单导入界面。本计划按实际源码盘点收敛范围：教师 CSV 名单导入和预检 API 已存在，只验证并补齐其教师端呈现缺口；账号模型、学号登录、管理端批量账号创建、共享 API 契约归笔记本 A，不改相关文件。

## 文件边界

- 教师门户：`frontend/apps/teacher-web/src/**` 及其页面测试、样式。
- 教师通知业务：优先限于 `backend/apps/notifications/**` 及对应测试；如课程申请或实验生命周期必须新增发事件入口，先复用既有事件机制并把改动收敛到单个集成点，不改账号模型、共享客户端、学生端或管理端文件。
- 不改 `backend/apps/accounts/**`、账号迁移、`frontend/packages/api-client/**`、`frontend/apps/student-web/**`、`frontend/apps/admin-web/**`。教师端名单导入沿用已有 API。
- `outputs/` 被 Git 忽略；本计划放在可跟踪的 `docs/开发指南/`。

## 阶段与提交

1. **计划与基线**：加入本计划，记录工作边界和验收顺序。验证：确认工作区只含本计划，分支从指定最新提交建立。提交：`docs: add bug-9 teacher workflow plan`。
2. **教师进度和评审入口**：检查现有学生/实验搜索，增加成绩筛选；从学生任务进入该任务的答卷/报告评审；给教学分析增加按学生搜索全课程实验，并让评分操作进入该学生、该实验的评审。验证：相关教师页面测试及 typecheck。提交：`fix(teacher): improve progress and analytics review flow`。
3. **教师实验设计与报告选项**：修复实验模板列表操作按钮在条件渲染时的对齐；核对发布表单中的报告必交设置与任务事实/学生呈现一致，只修复有证据的断点。教师模板编辑器当前已有题目、运行环境、预检和发布流程；汇总未指出额外缺项，不凭空增加功能。验证：模板、发布页面测试及 typecheck。提交：`fix(teacher): align template actions and report settings`。
4. **教师通知闭环**：补齐学生申请课程、实验发布成功/失败、实验结束及完成数通知。先确认现有事件、Outbox、通知唯一性/幂等模式，复用其持久化和权限规则。验证：通知相关 Django 测试及新增的必要回归测试。提交：`feat(notifications): notify teachers about enrollment and experiments`。
5. **集成验收**：审查分支全部差异，运行教师端测试、typecheck、构建，以及通知后端测试和文档指定检查；排除无关文件。最后才按仓库配置启动 Docker，确认服务重启和迁移状态，不在前面阶段更新本地 Docker 配置。若 Docker 环境缺失，记录具体阻碍和已完成的非 Docker 验证。提交：仅在本阶段确有代码修复时追加最后提交；无改动时不造空提交。

## 验收边界

- 实验进度搜索可按学生姓名、实验名筛选，并可按成绩查找；选择任务后能查看该学生该实验的固定提交和评分。
- 教学分析可查当前课程全部实验中的某学生记录；评分入口能落到对应评审对象。
- 模板列表按钮在不同模板状态下保持对齐；带/不带报告要求的发布行为分别正确。
- 教师收到课程申请和实验发布/结束通知；发布状态通知说明结果，结束通知的完成人数按已完成提交任务计算，重复事件不重复计数或重复发信。
- 全程不触碰笔记本 A 的独占文件；每个完结阶段先验证，再单独提交。
