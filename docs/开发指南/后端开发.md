## 目录与依赖

`manage.py` 位于 backend 根目录，业务应用在 `apps/`，配置和 ASGI 入口在 `education_experiment_platform/`。

当前项目要求 Python 3.14；声明的主要版本为 Django 6.1.1、DRF 3.18.1、Celery 5.6.3。准确依赖以 [pyproject.toml](../../backend/pyproject.toml)、[uv.lock](../../backend/uv.lock)及 [requirements](../../backend/requirements/) 为准，不另维护一套版本冻结表。镜像直接使用 requirements 文件；修改依赖时同时核对声明、锁文件和镜像安装入口。

定时任务使用 Celery beat 和项目调度配置，不从早期文档添加未被当前依赖锁采用的调度扩展。

## 主机开发

下面的 uv 命令在 `backend/` 执行，使用已安装的 Python 3.14：

```powershell
uv sync --locked --extra dev
$env:DJANGO_SETTINGS_MODULE = "education_experiment_platform.settings.test"
uv run --no-sync python manage.py check
uv run --no-sync python manage.py makemigrations --check --dry-run
uv run --no-sync python -m pytest
uv run --no-sync python -m ruff check apps education_experiment_platform --exclude migrations --force-exclude
uv run --no-sync python -m mypy apps education_experiment_platform
```

已有合适虚拟环境时可直接使用对应 Python。测试设置使用内存 SQLite 和模拟运行时；不能把单测结果当作 MySQL 事务、真实 Docker 或 Swarm 验收。

从仓库根目录可执行 `./scripts/verify/backend-local.ps1`，它会查找 Python 3.14 及开发依赖，执行 Django、迁移、pytest、Schema、Ruff、mypy 和 Compose 配置检查，不启动完整业务环境。

## 重做实验与成绩归并：问题分析报告及后端开发计划

记录日期：2026-11-06（北京时间）。状态：待后端开发；本次仅更新文档，不修改后端代码、数据库或正式接口。接口名称和字段为建议契约，尚未实现，需以最终 OpenAPI 为准。

### 问题与当前证据

教师需要对已截止实验中不及格的学生重新创建一次实验发布，设置独立开放时间、截止时间和参加学生。原发布保持截止状态，新发布生成独立工作区、报告与评审记录，但不能额外增加课程平均分的实验数量。

本次核对发现：

- `backend/apps/experiments/models.py` 的 TaskPublication 已有模板版本、评分表版本、受众、开放窗口和截止时间；本次查阅未见原发布与重做发布的显式关联字段。
- `backend/apps/reviews/models.py` 的 ReviewDecision 为追加型教师决定记录，含 score、教师及课程教师身份。首次与重做原始评分均应保留，不直接改写历史评分。
- `backend/apps/analytics/` 当前存在任务状态、完成率等统计；本次核对未确认其已支持下述重做关联、成绩封顶及计分项去重规则。
- `frontend/packages/api-client/src/index.ts` 已有 createPublication、publishPublication 等调用。缺口不是普通发布接口不存在，而是重做关系、定向受众、成绩归并和统计契约需要明确。
- 当前 HTML 原型只保存本地演示状态。此前原型采用“第二次成绩封顶后替换首次成绩”，与用户最终确认规则不符；后续前端必须改为两次成绩取最大值，不得以原型逻辑作为接口依据。

### 已确认的业务规则

1. 原实验已截止后，创建新 ID 的重做发布，关联老实验项目 ID；本项目建议使用原 TaskPublication.public_id 作为老 ID，重做 TaskPublication.public_id 作为新 ID。模板 ID 仅用于版本引用，不能代替发布关联。
2. 通过老 ID 能查询关联新 ID 及同一学生两次教师确认成绩。前端不必逐个查询每个学生、每个新 ID，后端应提供聚合查询。
3. 首次实际计分为首次教师确认分数；未提交按 0 分。第二次只使用教师最终确认成绩，AI 建议、批量采纳但未确认的分数不进入正式成绩。
4. 最终实际成绩 = max(首次成绩, min(第二次成绩, 60))。不能直接以第二次成绩覆盖首次成绩。
5. 首次、重做提交及教师评分记录均保留；实际成绩是派生结果或可重建的成绩投影。
6. 发布记录可以从 10 条增加到 11 条，但课程仍只有 10 个原始计分实验，重做发布不成为第 11 个计分项。

| 首次成绩 | 第二次成绩 | 实际成绩 |
| --- | --- | --- |
| 45 | 80 | 60 |
| 55 | 40 | 55 |
| 45 | 52 | 52 |
| 0（未提交） | 75 | 60 |

### 统计口径

- 单实验平均分：原发布应提交学生的实际成绩总和 / 原发布应提交学生数。未提交学生必须出现在分母，成绩为 0；不能只对有评审记录的学生求平均。
- 学生全部实验平均分：该学生全部原始应提交计分实验的实际成绩总和 / 原始应提交计分实验数。10 个实验始终除以 10；关联重做发布不另加分母。
- 课程全部实验平均分：全部原始学生任务实际成绩总和 / 原始应提交学生任务数。不同实验受众数不一致时，该值不一定等于各实验平均分的简单算术平均。
- 明确返回总分、应提交任务数、未提交数、平均分和统计范围，使前端能够解释结果。不得用只取前 100 条任务的前端分页列表计算全量统计。
- 计算采用十进制定点数，中间计算不提前取整，最终展示精度由接口声明；建议展示两位小数。

### 建议数据关系与约束

- 重做发布新增 `original_publication_id`（指向原始计分发布），`attempt_no=2`，`score_cap=60`；原发布反向查询重做列表。所有关联限同一课程。
- 重做学生任务关联 `original_task_id`，同时校验同一学生，不能用姓名匹配；原始计分项按原发布、学生唯一定位。
- 新发布沿用原模板与评分表快照，避免同一次计分项出现内容或总分口径漂移；如允许变更，需单独定义规则。
- 成绩投影建议返回 first_score、second_score、capped_second_score、effective_score、score_status、原/新发布 ID、原/新任务 ID、教师确认时间与投影版本。未提交、待评审、未开始、已确认应有独立状态，不因展示 0 分丢失状态。
- 重做取消、撤回、发布失败不应抹去首次成绩，也不能误计为新的正式计分项。

### 前后端接口对接需求（建议，非现有接口承诺）

| 能力 | 建议入口或扩展 | 输入/返回重点 |
| --- | --- | --- |
| 查询可重做学生 | 原发布下 eligibility 查询 | 原发布 ID、学生 ID、首次成绩、提交/确认状态、是否已安排重做、不可选原因 |
| 创建重做发布 | 扩展现有 createPublication，或原发布下 retakes 创建入口 | original_publication_id、学生 ID 列表、开放时间、截止时间、幂等键；返回新发布 ID 与关联关系 |
| 到日重新开放 | 沿用发布机制并补充未来窗口语义 | 区分计划创建、发布完成、学生可进入；需明确未来 window_start 是否足够，还是需要调度作业 |
| 查询关联与成绩 | 原发布下成绩聚合查询 | 老 ID 查询新 ID；分页返回同一学生两次成绩及 effective_score，不要求前端跨页拼接算分 |
| 教师确认重做分数 | 复用现有评分确认入口并触发归并 | 新任务/评审 ID、确认分数、并发版本；返回或可查询原任务最新 effective_score |

接口必须保留对象授权、幂等、并发检查和明确错误：跨课程关联、不属于原发布的学生、重复安排、非法状态、时间倒置、失效版本、成绩未确认。前端仅调整调用和展示，接口缺口由后端实现后更新 OpenAPI。

### 后端实施顺序

- [ ] B1 数据与迁移：定义原/新发布、原/新任务关系及唯一约束；历史发布默认原始计分项，不改变已有成绩。验证：历史数据迁移前后计分项数量和成绩一致。
- [ ] B2 重做创建：校验课程权限、原实验状态、学生资格、时间窗口、受众与幂等；保留原发布截止状态。验证：只有勾选学生收到新任务，重复请求不生成重复发布或任务。
- [ ] B3 定时开放：确认复用 window_start 的可行性；需要调度时定义重试、取消、失败与时区策略。验证：开放前不能进入，到点可进入且原发布仍截止；前端时间按 Asia/Shanghai 展示，接口传带时区时间。
- [ ] B4 成绩归并：教师确认后按最终公式生成/更新原计分项投影，保留两次原始记录；事务、锁和幂等事件保证重复确认不重复计分。验证：四个示例准确，低分重做不拉低首次成绩，AI 建议不影响实际成绩。
- [ ] B5 统计与查询：支持老 ID 查询新 ID 和成绩；实现单实验、学生全部实验与课程全量统计，排除重做分母。验证：未提交计 0，10 个实验加一次重做仍为 10 个计分项，分页不影响汇总。
- [ ] B6 接口交付：更新 serializer、路由、OpenAPI、接口示例和错误码；前端生成类型并对接发布、评审和教学分析。验证：教师安排 → 到日开放 → 学生提交 → 教师确认 → 原实验成绩与平均分刷新。
- [ ] B7 一致性与审计：提供投影重建和失败重试，记录原/新关联及教师确认信息。验证：重放事件、任务重试、查询缓存失效后成绩一致；无越权查询或跨学生回写。

### 待产品确认的边界（不视为已批准规则）

- 重做未完成或已提交待确认期间，建议继续保留首次成绩；第二次截止未提交按 0 处理后，由 max 公式保证首次成绩不下降。
- 当前只确认首次与第二次；第三次及以上重做暂不纳入范围，后端应阻止或明确拒绝，不能自行推导多次规则。
- 原始总分是否统一 100 分；若评分表总分不同，需先确认标准化方式，不能直接把原始分与 60 比较。
- 首次已经提交但还未评审的学生，是否允许以暂计 0 分安排重做；建议待教师确认后判断资格，未提交学生按 0 分可选。
- 确认截止后的“全部实验平均分”是按所有应提交任务加权，还是各实验均分等权；本报告建议前者，并在接口返回分母说明。
