# 后端开发

使用 Python 3.14，Django 项目位于 `backend`，依赖以 `backend/pyproject.toml` 和锁文件为准。日常用项目虚拟环境，不依赖宿主全局库。

```powershell
cd backend
.venv/Scripts/python.exe manage.py check --settings=education_experiment_platform.settings.test
.venv/Scripts/python.exe manage.py makemigrations --check --dry-run --settings=education_experiment_platform.settings.test
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check apps education_experiment_platform
.venv/Scripts/python.exe -m mypy apps education_experiment_platform
```

pytest 默认使用隔离测试设置。SQLite 不能证明 MySQL 锁行为；`test_assessment_concurrency` 要使用独立 MySQL 测试库。执行服务集成测试还需要真实 Docker、MinIO、ClamAV、Redis、Celery worker 与 Beat，详见[轻量答题验收](轻量答题验收.md)。

新代码草稿不依赖容器，运行与正式判题用短生命周期 stdio 容器。单元测试只能显式注入替身，应用没有 Fake 运行器或自动回退。测试种子使用 `seed_assessment_e2e`，要求显式课程和已审批运行资源，禁止生产环境运行。

数据库事实只通过既有事务、行版本与服务写入；交卷固定源代码与发布版本。结构删除使用新增迁移，历史迁移保留。先在独立库迁移和验收，再部署；不要对开发中的主库直接清空或用全局 Docker prune 回收。

存储资产先验证归属、路径和扫描状态；代码、附件、隐藏测试与参考解分别授权。日志不得记录隐藏输入输出、答案或应用密钥。
