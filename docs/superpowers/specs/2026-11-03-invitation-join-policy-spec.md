# 邀请码加入策略 Spec

## 背景

学生提交课程加入申请时，需要区分教师发放邀请码的直接加入路径和普通申请路径。

## 目标

- 提供有效邀请码时直接激活选课并进入课程。
- 未提供邀请码时创建待审核申请，必须等待教师同意。
- 前端明确展示两种路径的结果和操作文案。

## 功能需求

- F1: 有效邀请码使选课状态为已激活，并保留容量、邀请码有效期和使用次数校验。
- F2: 无邀请码的申请状态为待审核，与课程公开加入模式无关。
- F3: 前端在提交前说明两种路径，成功后根据实际状态提示已加入或等待审核。

## 验收标准

- AC1: 审核课程使用有效邀请码申请后返回 ACTIVE。
- AC2: 公开课程不填写邀请码申请后返回 PENDING。
- AC3: 前端类型检查、组件测试和构建通过。

## 不做的事

- 不改变邀请码解析、失效和容量规则。
- 不改变教师审核接口。
