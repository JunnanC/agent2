# 演示课程数据与学生退出课程 Spec

## 背景

学生端已有课程加入与退出接口及退出弹窗组件，但演示环境课程数量有限，且“我的申请”页面没有展示待审核申请的撤回入口。需要补充可用于测试的课程数据，并让学生能够在课程卡片和申请列表中管理自己的选课状态。

## 目标

- 增加默认演示数据中的课程数量和课程主题，便于学生端分页、搜索、加入和课程详情测试。
- 学生在已加入课程旁看到“退出课程”按钮，并能完成退出检查、填写原因和确认退出。
- 学生在待审核申请旁看到“撤回申请”按钮，并能撤回申请。
- 不改变已有课程加入、教师审核和邀请码流程。

## 功能需求

- F1: 演示数据种子在默认演示规模下创建比当前更多的独立课程，课程代码、内容和课程关系保持可重复执行且不重复创建。
- F2: 已激活课程在“我的课程”列表中显示“退出课程”操作；点击后读取最新选课状态和退出检查结果，允许填写退出原因并确认退出。
- F3: 待审核申请在“我的申请”列表中显示“撤回申请”操作；确认后调用撤回申请流程并刷新申请列表。
- F4: 退出或撤回成功后，课程列表、申请列表及相关学生数据缓存刷新，页面不需要手动刷新。

## 非功能需求

- N1: 保持现有 API 的幂等、版本校验和后端阻塞规则。
- N2: 课程数据种子不删除或覆盖用户已有数据。
- N3: 前端 TypeScript 类型检查、相关组件测试和学生端构建通过。

## 不做的事

- 不新增后端退出接口或改变退出规则。
- 不修改教师审核流程、课程搜索接口和邀请码解析规则。
- 不新增真实生产课程数据。

## 验收标准

- AC1: 执行默认演示种子后，课程数量多于当前默认值，且课程代码唯一；重复执行不会新增同一课程代码的重复记录。
- AC2: 已加入课程卡片显示“退出课程”，可在允许退出时确认并看到成功提示。
- AC3: 存在待审核申请时，“我的申请”显示“撤回申请”，确认后看到撤回成功提示且列表更新。
- AC4: 退出被后端阻塞时，页面展示阻塞原因并禁用确认按钮。
- AC5: `npm run typecheck`、学生端相关 Vitest 和 `npm run build:student` 通过。
