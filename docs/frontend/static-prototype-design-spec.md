# Edu Agent Platform 静态原型设计规范

> 用途：为后续 React 三端前端真实实现提供页面结构、视觉规范、交互规则、接口映射和验收依据。
>
> 适用范围：当前静态原型 `outputs/edu-agent-prototype/` 及后续 `frontend/apps` 下的学生端、教师端、平台管理端。
>
> 当前状态：本文件描述设计与实现约束；本轮不把静态原型改造成真实 API 应用，也不替代后端接口文档。

## 1. 文档定位

本规范将当前静态原型中的视觉和交互决策整理为可执行的前端交接说明，重点解决以下问题：

- 三端页面如何组织，避免将不同角色的操作混在一起。
- 页面如何使用统一的布局、颜色、间距、状态和反馈方式。
- 学生实验工作台如何保持“编辑、运行、保存、提交”主线，不堆叠重复信息。
- 静态演示数据在迁移到真实 API 时，如何对应资源、状态、权限和异步作业。
- 哪些信息属于学生可见内容，哪些信息只应显示在教师端或平台管理端。

本文件中的“应”表示实现约束，“建议”表示可在组件设计阶段评估，“示例”表示静态原型中的演示内容，不代表真实业务数据。

## 2. 原型范围与文件

### 2.1 原型目录

当前静态原型主要位于：

```text
D:\all_of_project\edu-agent-platform\outputs\edu-agent-prototype\
```

重点文件如下：

| 文件 | 职责 | 真实实现迁移提示 |
| --- | --- | --- |
| `index.html` | 门户首页、学生端/教师端部分页面入口和演示布局 | 拆分为路由页面和共享壳层 |
| `app.js` | 门户页面交互、模拟数据、导航、菜单和部分状态 | 替换为页面级状态管理和 API hooks |
| `styles.css` | 全局颜色、排版、面板、导航和门户布局 | 提取为 design tokens 与组件样式 |
| `student-workbench.html` | 学生实验工作台静态结构 | 拆分为工作台布局、面板和编辑器组件 |
| `workbench.js` | 工作台章节、报告、测试用例和拖拽交互 | 接入 session、checkpoint、报告和提交 API |
| `student-course.css` | 学生课程相关页面补充样式 | 与学生端课程组件合并，避免重复 token |
| `workflow-enhancements.css` | 任务流、状态和页面增强样式 | 迁移为业务组件样式，减少全局选择器 |

### 2.2 参考资料

接口和真实接入规则以以下文档为准：

- `docs/frontend/frontend-api-endpoint-catalog.md`
- `docs/frontend/frontend-backend-integration-guide.md`

上述资料是接口参考，不是对页面视觉的替代。若接口字段与本规范的演示文字不一致，应优先采用接口契约，再保持本规范的布局和交互原则。

### 2.3 原型与真实前端的边界

当前原型使用本地模拟数据和 `localStorage`，用于演示页面结构和操作路径；它不代表以下能力已经真实可用：

- 登录会话、CSRF 和权限控制。
- 课程、任务、实验实例和工作区的服务端状态。
- 报告附件上传、扫描、提交和评审。
- 模板发布、实验发布、批量导入等异步作业。
- SSE 实时刷新、冲突处理和审计日志。

真实实现不能仅复制 DOM 和本地事件，应将静态交互映射到资源状态、`allowed_actions`、`blockers`、版本号和异步作业状态。

## 3. 产品信息架构

平台按角色拆分为学生端、教师端和平台管理端。三端可以复用视觉组件，但不应复用同一套业务导航或信息权限。

### 3.1 学生端

学生端围绕“选课—学习—完成实验—提交报告—查看反馈”组织：

1. 首页：查看近期课程、截止任务、日历和通知入口。
2. 我的课程：查看已加入课程和课程学习入口。
3. 加入课程：输入邀请码、提交申请、查看申请状态。
4. 我的实验：按状态查看实验任务和进入工作区。
5. 课程详情：查看章节、材料、公告、日历、任务和课程问答。
6. 任务详情：查看阶段任务、开放/截止时间、完成条件和可执行操作。
7. 实验工作台：完成章节任务、运行测试、编辑报告、保存和提交。
8. 通知：处理截止提醒、报告评审、平台消息和风险提示。
9. 个人菜单：查看个人资料、账号设置和退出登录。

学生端不展示教师配置过程、平台资源治理、实例资源规格、内部错误堆栈、工作区内部上下文或不影响学生决策的资源状态。

### 3.2 教师端

教师端围绕“建设课程—发布实验—跟踪过程—完成评审”组织：

1. 教学概览：查看课程、待处理申请、待评审报告和风险概览。
2. 我的课程：查看课程基本资料、章节、材料、公告和日历。
3. 选课管理：审核申请、管理邀请码、导入学生和移除学生。
4. 实验设计：维护实验模板、章节任务、说明和报告模板。
5. 实验发布：预检、发布、撤回、关闭实验并查看发布状态。
6. 学生过程：按学生和任务查看进度、工作区状态和风险信号。
7. 评审中心：查看待评审报告、Rubric、批注、相似度和评审决定。
8. 教学分析：查看课程学习、完成率、逾期和评审质量趋势。

教师导航应将入口按工作流分组，避免把每个接口都直接做成一个导航项。

### 3.3 平台管理端

平台管理端围绕“治理—运行—安全—审计”组织：

1. 平台总览：查看用户、课程、资源和治理告警。
2. 用户与资格：处理教师资格、管理员授权和用户状态。
3. 课程治理：查看异常课程、冻结/解冻和资源使用。
4. 模板预检：查看预检失败汇总和模板问题。
5. 镜像与资源：管理镜像、规格、运行时适配器和配额。
6. 配额与实例：查看实例、session、孤儿资源和回收任务。
7. 异常与补偿：处理实验异常、扫描异常和失败任务补偿。
8. 审核监管：查看运行日志、操作日志和 Trace ID。
9. Agent 与集成：管理模型路由、工具策略、成本和评测。
10. 分析与运维：查看平台稳定性、吞吐和运营指标。

平台端可显示资源状态，但这些信息不应泄漏到学生工作台。

## 4. 全局布局

### 4.1 页面层级

门户页面采用三层结构：

```text
顶部导航（身份、主导航、头像菜单）
  └─ 页面主体（面包屑、操作区、内容面板）
      └─ 反馈层（Toast、确认弹窗、抽屉、加载和错误状态）
```

顶部导航和主体内容应由应用壳层统一渲染；页面内部只负责页面标题、操作区和业务内容。不要在每个页面重复创建一套导航和个人菜单。

### 4.2 顶部导航

- 顶栏高度约 `64px`。
- 左侧是产品标识和当前门户名称。
- 中间是当前角色可用的主导航。
- 右侧是通知入口、头像和小型个人菜单。
- 头像点击后，在头像下方显示紧凑菜单，不应出现覆盖右侧大面积区域的巨型浮层。
- 当前页面使用明显但克制的选中态，避免增加大量辅助文字。

学生端建议保留：`首页`、`我的实验`、`我的课程`、`加入课程`、`通知`。

教师端建议收拢为：

- `教学概览`
- `课程与实验`：我的课程、选课管理、实验设计、实验发布
- `学生与评审`：学生过程、评审中心
- `教学分析`

平台端可使用分组导航或侧栏导航，避免在窄屏中一次展示全部治理入口。

### 4.3 面包屑

- 面包屑紧贴顶部导航，距导航的间距应小于其与主要内容的间距。
- 面包屑使用低对比度小字号，作为定位信息，不应抢过页面主要内容。
- 课程、任务、工作台页面应保留可点击的上级路径。
- 工作台中的章节切换不应全部堆进面包屑，应使用章节菜单或阶段导航。

### 4.4 主体栅格

- 桌面主体最大宽度约 `1520px`。
- 主体左右内边距约 `32px`。
- 常规面板间距约 `15px`。
- 面板内边距约 `17px–18px`。
- 页面操作区与内容区应保持同一栅格对齐。
- 小于约 `1050px` 时，双栏页面逐步变为上下排列；小于约 `760px` 时，导航收起为菜单。

### 4.5 页面操作区

页面操作区只保留当前页面最重要的操作：

- 一个主要按钮对应一个主任务。
- 与主按钮重复的“进入”“查看”“继续”等按钮应合并。
- 低频操作放入次级菜单或更多操作，不与主按钮争夺空间。
- 删除无效的进度提示、重复说明块和只展示接口字段的卡片。

## 5. 视觉设计规范

### 5.1 颜色 token

当前原型以暖白背景、深灰文字和低饱和青绿色为主色，真实实现应将其抽取为 CSS variables 或主题 token：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ink` | `#253238` | 主文字、标题、图标 |
| `--muted` | `#748087` | 辅助文字、时间、说明 |
| `--line` | `#dfe4e1` | 分隔线、边框 |
| `--paper` | `#f1f0eb` | 页面背景 |
| `--surface` | `#ffffff` | 面板、弹窗、编辑区 |
| `--surface-soft` | `#f7f7f3` | 次级背景、输入区域 |
| `--teal` | `#2f7069` | 主色、主要操作、选中态 |
| `--teal-soft` | `#e7f0ed` | 主色浅背景 |
| `--amber` | `#a76d21` | 警告、待处理 |
| `--amber-soft` | `#fbf1df` | 警告浅背景 |
| `--green` | `#4d7d63` | 成功、已完成 |
| `--green-soft` | `#e8f1eb` | 成功浅背景 |
| `--blue` | `#506d84` | 信息、处理中 |
| `--blue-soft` | `#e9eff3` | 信息浅背景 |
| `--red` | `#a6534d` | 错误、危险操作 |
| `--red-soft` | `#f7e9e6` | 错误浅背景 |

原型中圆角约为 `2px`，整体保持轻量、克制的面板感。真实实现可以为输入框、菜单和按钮增加少量圆角，但不应变成高圆角卡片风格。

### 5.2 字体层级

建议使用系统无衬线字体，中文优先使用系统中文字体；层级如下：

| 层级 | 建议字号 | 用途 |
| --- | --- | --- |
| 页面主标题 | `24px–28px` | 只用于页面真正的主标题 |
| 区块标题 | `16px–18px` | 面板标题、任务标题 |
| 正文 | `14px–15px` | 主要说明和列表内容 |
| 辅助文字 | `12px–13px` | 时间、状态解释、次要信息 |
| 标签文字 | `11px–12px` | 状态标签、筛选条件 |

页面不再新增大段引导型大标题。若页面已有面包屑和明确内容标题，避免再加一层重复的营销式副标题。

### 5.3 面板、边框和间距

- 面板使用白色背景、细边框和轻微阴影或无阴影。
- 分组优先使用间距和分隔线区分，不要用过多卡片制造信息噪声。
- 主要内容区域应比状态提示区域更大。
- 测试用例、报告编辑器和任务说明属于工作内容，应优先获得可用空间。
- 非关键提示如“预计用时”“当前进度”“阶段总数”等，若与任务说明重复，应删除或降级为辅助文字。

### 5.4 按钮与状态标签

- 主要按钮使用 `--teal`，一个区域最多一个主要按钮。
- 次要按钮使用白底边框或浅色背景。
- 危险按钮使用 `--red`，必须配合确认弹窗。
- 已完成、进行中、待处理、失败分别使用绿色、蓝色、琥珀色、红色状态标签。
- 状态标签必须有文本，不仅依赖颜色表达。
- 禁用按钮应说明阻塞原因，不能只降低透明度后让用户猜测。

## 6. 共用组件和交互规则

### 6.1 共享组件清单

建议在真实前端抽取以下组件：

```text
AppShell
TopNav
Breadcrumbs
AvatarMenu
PageHeader
Panel
StatusBadge
FilterBar
DataTable
EmptyState
LoadingState
ErrorState
Toast
ConfirmDialog
Drawer
DateCalendar
RichTextEditor
ResizablePane
AsyncJobProgress
```

组件应优先处理布局、状态和可访问性；业务页面负责组合组件，不在组件内部硬编码某个课程或实验的文字。

### 6.2 加载、空状态和错误

每个 API 页面至少需要：

- 初次加载状态：骨架屏或明确的加载提示。
- 空状态：说明当前没有数据，并提供唯一必要的下一步动作。
- 错误状态：说明读取失败，提供重试入口。
- 权限状态：说明无权查看，而不是显示空白页面。
- 异步状态：显示“已提交/处理中/成功/失败”而不是只显示瞬时 Toast。

### 6.3 弹窗、抽屉和 Toast

- 删除、撤回、退出实验、拒绝申请等不可逆或有数据影响的操作必须确认。
- 确认弹窗应说明影响范围、默认选项和取消方式。
- 低风险成功反馈可使用 Toast，但重要提交结果要保留在页面状态中。
- 抽屉适合查看详情、申请说明、通知内容和筛选，不适合承载完整编辑流程。

### 6.4 重复功能收敛

实现过程中应遵守“一项任务一个主入口”：

- 页面上已有“进入工作台”时，不再额外放“继续实验”“打开任务”两个等价按钮。
- 页面上已有“保存”时，不再为同一内容增加“暂存”“保存草稿”两个并列按钮；可在保存按钮旁显示保存状态。
- 页面上已有“查看报告”时，不再重复放“报告详情”“查看提交”两个同义按钮。
- 状态信息应统一进入状态标签或详情页，不要复制到多个统计卡片。

## 7. 学生门户页面

### 7.1 首页/概览

首页以“接下来要做什么”为核心，但不使用重复的引导式大标题。建议布局：

```text
顶部导航
面包屑
┌──────────────┬──────────────────────────────┐
│ 今日/近期任务 │ 日历：每天显示截止任务数量       │
│ 轻量任务列表  │ 点击日期弹出小框显示任务          │
├──────────────┴──────────────────────────────┤
│ 最近课程/最近通知（按实际需要保留）              │
└───────────────────────────────────────────────┘
```

日历规则：

- 每日格子显示当天截止任务数量；没有任务时不显示占位文字。
- 点击日期后使用小型浮层显示对应课程和实验任务。
- 浮层中的任务可直接跳转到课程详情、任务详情或工作台。
- 不再保留“你好，某某”“把今天的实验推进一点”等大段欢迎内容。
- 不再保留与任务列表重复的“继续你的实验”大块。

### 7.2 我的课程

只展示学生已加入或已通过的课程及其必要状态：

- 课程名称、教师、课程时间或学期。
- 学习进度和最近一次进入位置。
- 进入课程详情的单一主操作。

页面不应再次展示“查看课程进度、实验任务与最近活动”这类重复说明大标题，也不应默认显示课程推荐块。

### 7.3 加入课程

加入课程页面承担明确的加入流程：

1. 输入邀请码或课程码。
2. 展示匹配到的课程基础信息。
3. 确认提交申请或直接加入。
4. 展示申请处理中、已通过、已拒绝、已移除等状态。
5. 提供进入课程的唯一主操作。

页面不应显示“找到适合你的课程”推荐大块，也不应在加入课程页面重复渲染课程目录或我的课程内容。无匹配结果时只显示简洁的错误说明和重新输入动作。

### 7.4 课程学习详情

课程详情页建议采用左侧目录、右侧内容：

```text
┌──────────────┬────────────────────────────────┐
│ 课程章节目录  │ 课程基本信息/当前章节内容         │
│ 材料          │ 实验任务、公告、日历、问答入口     │
│ 实验任务      │                                 │
└──────────────┴────────────────────────────────┘
```

页面内容：

- 课程基本信息、教师、选课状态和课程时间。
- 章节目录和未开始、学习中、已完成状态。
- 章节材料、实验任务、公告和课程日历。
- 实验任务直接进入任务详情或实验工作台。
- 课程问答入口连接课程 Agent 或问答接口。
- 未选课课程显示“申请加入课程”；已加入课程显示选课状态。

### 7.5 我的实验与任务详情

任务列表显示任务名称、课程、当前状态、截止时间和唯一主操作。任务详情页进一步显示：

- 任务状态、开放时间、截止时间和完成条件。
- 当前阶段、阶段任务和完成路径。
- 开始任务、进入工作区、完成任务等由后端允许的操作。
- 阻塞原因及允许的状态迁移。
- 申请延期、查看延期状态、重试失败任务。
- 装载中的阶段进度和失败原因。

任务详情不应复制工作台中的编辑区，也不应显示教师内部配置字段。

### 7.6 通知与学习支持

通知页用于集中处理：

- 截止日期提醒。
- 报告退回、评审完成和批注更新。
- 课程公告和平台消息。
- 任务逾期、长期未进入工作区等风险提示。
- 个性化学习建议。

通知项需要支持标记已读，并可直接跳转到课程、任务、报告或评审结果。页面不再添加“通知与学习支持”这种大段描述型标题，使用简洁的页面定位和列表分组即可。

## 8. 教师门户页面

### 8.1 教学概览

教学概览聚合当前工作流中的待处理事项：

- 课程数量和状态。
- 待审核选课申请。
- 待评审报告。
- 即将开始、即将截止或异常的实验发布。
- 需要关注的学生风险信号。

统计数据只用于导航和优先级判断，点击后必须进入真实列表或详情，不要堆叠没有后续动作的数字卡片。

### 8.2 我的课程与课程设置

课程详情集中显示：

- 课程基本资料和当前学期。
- 学生人数、待审核申请和课程状态。
- 课程章节、材料、公告、日历和问答。
- 课程 Agent 配置入口。
- 课程资源与实验发布状态。

课程编辑和查看应分开，避免在只读页面同时出现多个重复编辑按钮。

### 8.3 选课管理

选课管理形成完整的申请闭环：

- 按待审核、已通过、已拒绝、已移除筛选。
- 查看申请详情和申请说明。
- 审核通过或拒绝申请。
- 管理邀请码。
- 批量导入学生，包含导入预检和任务进度。
- 移除学生前显示影响检查。

表格操作应将“查看详情”作为行主操作，其余审核、移除和更多动作收敛到操作菜单。

### 8.4 实验设计与模板编辑

模板编辑页支持：

- 模板和模板版本管理。
- 章节新增、编辑、排序。
- 章节下任务新增、编辑、排序。
- 实验说明和实验报告模板配置。
- 自动检查规则设置。
- 模板资源、镜像和文件资产管理。
- 版本发布、撤回和克隆。

报告模板设置必须明确对应学生工作台中的报告编辑区。教师保存模板后，学生端以当前发布版本为准，不应直接读取教师尚未发布的草稿。

### 8.5 实验发布管理

发布页支持完整生命周期：

1. 创建发布草稿。
2. 设置开放时间、截止时间和发布范围。
3. 运行模板预检。
4. 查看预检结果和阻塞原因。
5. 发布、撤回或关闭实验。
6. 查看发布后的任务数量和任务状态。
7. 查看实例配置、资源规格和运行时选择。
8. 发布失败时显示阶段、错误码和 Trace 信息。

发布按钮应根据后端 `allowed_actions` 决定是否可用，不能只根据前端表单是否填写来判断。

### 8.6 学生过程

过程页可按学生查看：

- 任务进度、当前阶段和最近活动。
- 工作区 session 状态。
- 受控查看学生工作区。
- 操作回放。
- 执行结果和报告提交状态。
- 逾期、失败、长时间未活动等风险标记。

学生工作区受控查看必须显式提示教师的查看权限和数据范围，避免将教师查看行为误认为学生操作。

### 8.7 评审中心

评审中心支持：

- 待评审提交列表。
- Rubric 评分。
- 报告批注、批注修订和撤回。
- 提交预览。
- 相似度检测结果。
- 评审决定。
- 评审进度和质量统计。

学生端工作台只显示编辑、保存和提交相关状态；评审意见、报告版本历史和教师评分统一放在提交详情/通知/评审结果页面，不在编辑器顶部继续挤占空间。

## 9. 平台管理页面

### 9.1 平台治理总览

显示用户、教师资格、管理员授权、课程数量、异常课程、资源使用、治理告警、模板预检失败和报告扫描异常汇总。每项汇总都必须能进入对应列表或处理页面。

### 9.2 运行资源管理

支持镜像审批、资源规格、运行时适配器健康、配额使用、扩缩容策略、运行实例、工作区 session、孤儿实例和资源回收。

资源管理只在平台端显示。学生端最多显示“正在准备/可用/不可用以及下一步动作”，不显示内部镜像、规格、主机或资源池信息。

### 9.3 安全与异常中心

集中展示：

- 安全策略和网络白名单。
- 实验任务异常。
- 报告扫描异常。
- 模板预检失败。
- 失败任务补偿。
- 运行和操作日志。
- Trace ID 检索。

错误详情要对不同角色脱敏。教师可看到与课程发布和学生任务有关的错误；平台管理员才可看到基础设施诊断细节。

### 9.4 评审与 Agent 治理

平台端可展示评审质量汇总、相似度检测统计、Agent 模型路由、工具策略、使用成本、评测套件、评测运行和课程 Agent 使用情况。

这些页面应服务于治理和决策，不应把低层接口字段原样堆成表格。

## 10. 学生实验工作台

工作台是学生端最复杂的页面，核心目标是让学生连续完成“查看说明—编辑—运行—修正—保存—提交”。

### 10.1 总体布局

建议结构：

```text
工作台顶部：课程/实验定位、章节菜单、终端、文件编辑、结果预览、退出实验
┌───────────────────────┬─────────────────────────────────┐
│ 实验任务（紧凑）        │ 终端/文件编辑/结果预览工作区        │
│ 菜单按钮 + 章节列表     │ 可切换的运行与编辑面板              │
├───────────────────────┼─────────────────────────────────┤
│ 实验说明 / 实验报告     │ 测试用例（紧凑区域）                │
│ 报告编辑器占主要高度    │ 测试运行或提交报告动作              │
└───────────────────────┴─────────────────────────────────┘
```

工作台右侧不再保留独立的“实验工作区”块，也不显示教师内部的实验上下文、资源状态等非必要信息。

### 10.2 顶部区域与退出实验

- 退出实验不放在头像旁边。
- 退出实验与“终端、文件编辑、结果预览”处于同一行，并靠右放置。
- 顶部只保留必要的定位信息和工作区切换。
- 退出实验点击后打开确认弹窗，说明实例、实验记录、报告草稿和 checkpoint 是否保留。
- 弹窗至少提供“保留并退出”和“退出且不保留”两个明确选择，以及取消。
- 若服务端返回 `blockers`，弹窗应优先解释阻塞原因，不允许用前端强制关闭绕过后端约束。

### 10.3 章节菜单

- 在左侧实验任务标题旁放置三横线菜单标识。
- 点击后展开章节任务菜单。
- 菜单显示章节名称、完成状态和当前选中项。
- 点击章节后，左侧下方工作区域切换到该章节的说明和报告。
- 每完成一个阶段任务，都要进入对应的实验报告编辑和提交流程。
- 左侧不再把“实验说明”和“实验章节”作为重复块堆叠；采用章节菜单 + 两个并排可点击选项：`实验说明`、`实验报告`。

### 10.4 实验说明与实验报告

左侧主要空间留给实验说明和实验报告，二者应使用并排选项切换，而不是上下同时占用高度。

实验说明页显示：

- 当前章节任务说明。
- 完成条件和必要的输入输出信息。
- 相关材料或提示。
- 与当前阶段直接相关的测试要求。

实验报告页显示：

- 教师发布的报告模板内容，自动填充到当前报告草稿。
- 富文本编辑器组件导航位于报告框最上方。
- 工具栏下方保留一条分隔线。
- 分隔线以下的剩余空间全部用于编辑文本。
- 不再内嵌第二个文本框。
- 不显示“第 N 阶段·路由与端口检查实验报告”之类重复的大标题；标题和阶段信息由页面定位或轻量标签表达。

报告编辑器建议支持标题、粗体、斜体、列表、引用、代码块、链接、撤销/重做等模板实际允许的能力。最终可用工具应由教师模板和后端策略决定。

### 10.5 编辑器保存状态

报告顶部只保留编辑和保存相关信息：

- `草稿` 和 `保存阶段` 等状态靠右排列。
- 两个状态块尺寸相同，文字短且可读。
- 当工作台与报告之间的分隔条被拉到较小时，两个状态块按比例缩小，但不能被覆盖。
- 使用 `min-width`、`flex-shrink` 和必要的换行策略保证可见性。
- 保存中、已保存、保存失败、存在冲突应有清晰状态。

不在工作台编辑区显示评审意见和报告版本历史；这些信息统一放到报告提交详情或评审结果页面。

### 10.6 工作区面板

终端、文件编辑、结果预览是工作区的同级入口，切换时保持统一的标签样式。面板内部显示：

- 运行/停止等与当前面板相关的操作。
- 必要的加载、失败和重试状态。
- 结果预览或文件内容。

不要将执行记录作为独立大区放在工作台底部。执行详情如需保留，应作为结果预览中的可展开详情或单独页面入口。

### 10.7 测试用例

- 测试用例区域保持紧凑，给真实用例更多空间。
- “本阶段共 3 项·尚未运行”一类提示应与测试用例标题并排靠右，减少占用面积。
- 删除重复的大提示块和无效统计文字。
- 测试用例支持单项运行、全部运行、查看结果和失败原因。
- “测试运行”与“提交报告”放在测试区域下方，按当前状态显示一个主要动作和必要的次要动作。
- 未通过测试时，提交动作应根据后端允许状态显示阻塞原因，而不是静默禁用。

### 10.8 可调整分隔条

实验报告、工作台和测试用例之间的分隔条支持鼠标长按拖动：

- 拖动时显示可拖动光标和高亮边界。
- 设定最小宽度/高度，避免编辑区或操作区消失。
- 分隔条到达最小值时，报告编辑器仍可输入，草稿/保存状态仍可见。
- 测试用例区不能无限扩大，必须保留编辑区和工作区的最低可用空间。
- 用户的面板尺寸可以保存在本地偏好，但不能覆盖服务端任务状态。
- 键盘用户应能通过可访问的调整控件改变面板比例，或至少获得合理的移动端替代布局。

### 10.9 退出实验确认

弹窗需要明确说明：

- 实例是否继续运行。
- 实验记录是否保留。
- 报告草稿是否保存。
- checkpoint 是否保留。
- 未保存内容是否会丢失。
- 退出后能否从任务详情重新进入。

弹窗文案应根据服务端能力动态生成，不承诺后端无法保证的保留行为。

## 13. 状态、并发和异步任务

### 13.1 `allowed_actions` 和 `blockers`

所有带操作的页面应以服务端返回的 `allowed_actions` 为最终依据。例如：

- 任务详情中的开始、进入、重试、申请延期。
- 教师端的审核、发布、撤回、关闭。
- 工作台中的保存、创建 checkpoint、恢复、提交报告、退出。

`blockers` 应展示为用户能理解的原因，并提供可执行的解决路径。前端不能仅依据本地按钮状态猜测业务是否允许。

### 13.2 会话和安全请求

- Cookie session 请求使用 `credentials: "include"`。
- 首次写请求前获取 CSRF，并发送 `X-CSRFToken`。
- 写操作使用 `Idempotency-Key`，尤其是提交、发布、审核、导入和创建实例。
- 不在日志中记录 session cookie、CSRF token、workspace token、下载 token、密钥、密码或完整文件内容。

### 13.3 版本和并发

- 更新已有资源时使用最新 `ETag` 和 `If-Match`。
- 收到 `412 ROW_VERSION_CONFLICT` 时，保留用户本地编辑内容，提示重新获取并合并，而不是直接覆盖。
- 报告自动保存失败不能静默丢失文本。
- 工作台面板尺寸、草稿内容和服务端报告版本要分开管理。

### 13.4 异步作业

`202` 只表示作业已接受，不代表成功。前端应显示：

1. 已提交。
2. 处理中。
3. 成功或失败。
4. 失败原因和重试入口。

适用场景包括实例装载、模板预检、批量导入、报告扫描、相似度检测、发布和补偿。

### 13.5 SSE 与轮询

SSE 可用于刷新提示、运行进度和异步任务状态，但最终页面状态必须以 REST 查询结果为准。断线后需要重新拉取资源，不能将客户端最后一次事件当作最终事实。

## 14. 安全、权限和数据可见性

### 14.1 学生可见性

学生只看到完成学习任务所需的信息：

- 课程、章节、任务说明、测试结果。
- 报告草稿、保存状态、checkpoint、提交结果。
- 教师已发布的评审结果和必要反馈。

学生不应看到：

- 教师内部实验上下文。
- 资源规格、镜像细节、实例内部状态。
- 平台操作日志、Trace 详情和治理告警。
- 其他学生的学习进度和提交内容。
- 未发布的报告模板、教师草稿或内部评分策略。

### 14.2 教师可见性

教师可查看自己课程范围内的学生、任务、工作区受控信息、报告、评审和风险信号。跨课程和平台资源信息应由后端权限限制，不在前端通过隐藏按钮替代授权。

### 14.3 平台管理员可见性

平台管理员可根据权限查看运行资源、异常、审计和治理信息。错误详情需要按角色脱敏，避免在教师或学生页面泄露基础设施信息。

## 15. 响应式与可访问性

### 15.1 响应式

- `1050px` 左右：双栏内容开始收缩，右侧辅助区可降级为抽屉或下方区域。
- `760px` 左右：顶部导航收起，表格转为卡片或横向滚动，工作台改为单列标签切换。
- 报告编辑器始终保留可输入高度，不因测试用例或提示区增长而被压缩到不可用。
- 可调整分隔条在触屏环境下提供按钮或预设比例替代。

### 15.2 可访问性

- 三横线章节菜单必须有可读的 `aria-label`。
- 颜色状态必须同时有文字或图标，不依赖颜色。
- 弹窗打开后焦点进入弹窗，关闭后返回触发按钮。
- 富文本编辑器工具栏按钮要有名称、快捷键提示和禁用状态。
- 拖动分隔条应提供键盘替代或固定比例切换。
- 所有表单控件有明确标签和错误说明。
- 页面标题和区域标题遵循合理的 heading 层级，但不要为了视觉效果增加重复标题。

## 16. 原型与真实实现的差异清单

真实实现时应主动补齐以下差异：

| 原型表现 | 真实实现要求 |
| --- | --- |
| 本地模拟数据 | 使用 API client、缓存和请求状态 |
| `localStorage` 保存草稿/布局 | 草稿走报告 API，布局偏好可本地保存 |
| 点击按钮直接改变文字 | 根据服务端响应、版本和异步任务更新 |
| 静态状态标签 | 由资源状态、`allowed_actions` 和 `blockers` 计算 |
| 假设实例可立即进入 | 显示装载作业和 session 有效期 |
| 直接提交报告 | 先做附件扫描、冲突检查和提交前校验 |
| 模拟测试结果 | 显示 execution-run 状态和单次执行详情 |
| 简单退出 | 根据保留能力和未保存状态显示确认选项 |
| 视觉隐藏内容 | 从数据查询和组件树上真正不渲染无权限内容 |

## 17. 推荐实施顺序

### 第一阶段：学生学习闭环

1. 应用壳层、导航、头像菜单和面包屑。
2. 学生首页日历、截止任务和跳转浮层。
3. 我的课程、课程详情和加入课程。
4. 任务列表、任务详情和状态迁移。
5. 工作台布局、章节菜单、实验说明和报告编辑器。

### 第二阶段：教师内容与发布闭环

1. 教师导航收拢和教学概览。
2. 选课管理和导入作业。
3. 实验模板、章节任务和报告模板编辑。
4. 模板预检、实验发布、撤回和关闭。

### 第三阶段：工作台可靠性与评审

1. session、快照和 checkpoint。
2. 测试运行、执行记录详情和操作回放。
3. 报告附件、扫描、版本和提交状态。
4. 教师学生过程、评审中心、批注和相似度。

### 第四阶段：平台治理

1. 平台治理总览。
2. 镜像、规格、配额、实例和工作区监控。
3. 异常、补偿、审计日志和 Trace 查询。
4. Agent 路由、工具策略、成本和评测。

## 18. 验收清单

### 页面和导航

- [ ] 三端导航按角色和工作流组织，没有把每个接口都做成入口。
- [ ] 面包屑靠近顶部导航。
- [ ] 头像菜单为头像下方的小型弹出菜单。
- [ ] 页面不出现重复的大段引导标题或重复说明块。
- [ ] 加入课程页面不显示课程推荐大块。
- [ ] 重复功能按钮已合并为一个主操作。

### 学生首页和课程

- [ ] 日历每日显示截止任务数量。
- [ ] 点击日期显示小型任务浮层。
- [ ] 浮层中的任务可跳转到对应页面。
- [ ] 课程详情能够显示章节、材料、公告、日历、任务和问答入口。
- [ ] 加入课程显示邀请码、匹配结果和申请状态。

### 学生工作台

- [ ] 退出实验与终端、文件编辑、结果预览同一行并靠右。
- [ ] 没有独立的“实验工作区”块。
- [ ] 学生看不到教师/平台内部实验上下文和资源状态。
- [ ] 三横线章节菜单可以切换任务。
- [ ] 实验说明和实验报告使用并排选项切换。
- [ ] 报告顶部只有富文本工具栏和分隔线，下面是主要编辑区。
- [ ] 没有重复的阶段报告大标题和内嵌第二文本框。
- [ ] 测试用例区域紧凑，真实用例拥有主要空间。
- [ ] 测试运行和提交报告动作位置清晰。
- [ ] 分隔条拖到最小值时，报告编辑和保存状态仍可用。
- [ ] 退出弹窗说明实例、记录、草稿和 checkpoint 的保留情况。

### 教师与平台

- [ ] 教师可以审核选课、管理邀请码和导入学生。
- [ ] 教师可以编辑实验章节、报告模板和自动检查规则。
- [ ] 教师可以预检、发布、撤回和关闭实验。
- [ ] 教师可以查看学生过程和评审结果。
- [ ] 平台管理员可以查看资源、异常、补偿和审计信息。
- [ ] 学生、教师、平台管理员的数据可见范围符合角色权限。

### 真实接入

- [ ] Cookie session 使用 `credentials: "include"`。
- [ ] 写请求包含 CSRF 保护和 `Idempotency-Key`。
- [ ] 更新请求使用 `ETag`/`If-Match`。
- [ ] `412` 冲突不会覆盖用户编辑内容。
- [ ] `202` 异步任务有完整进度和失败状态。
- [ ] SSE 断线后会通过 REST 重新确认最终状态。
- [ ] 错误展示错误码、原因、重试入口和必要的 Trace ID。
- [ ] 日志不包含 token、密钥、密码和完整文件内容。
