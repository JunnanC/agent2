# 数据与接口

核对日期为 2026-11-19。全量字段以 `backend/apps` 模型、应用路由与生成的 OpenAPI 为准。

## 事实关系

| 链路 | 当前模型 |
| --- | --- |
| 模板与发布 | Template → TemplateVersion → TaskPublication → ExperimentTask |
| 公开与私有题目 | TemplateTask、PublicationTask；question_spec 与 marking_spec 分开，学生响应只读白名单 |
| 草稿 | AnswerDraft；按题目、语言独立的 CodeDraft；AssessmentSession 保存当前编程题 |
| 不可变提交 | 选择题由 AssessmentSection 指向当前 SectionSubmission；编程题通过后创建唯一的 ProgrammingSubmission |
| 工作区 | StudentWorkspace 与学生任务一对一；WorkspaceSnapshot 保存每次运行和正式提交的代码 |
| 报告 | TaskPublication 关联报告模板；ReportSubmission 保存学生当前附件、状态和教师评分 |
| 评分 | 选择题按答对题数、编程题按通过题数折算；报告由教师评分；PartRedo 记录各部分补做期限 |
| 量表 | Rubric → RubricVersion → RubricCriterion |
| 归档 | ArchiveJob → ArchiveManifest、ArchiveVerification、导出授权 |
| 运行与回收 | 编程工作区使用 Docker Local，限制为 0.5 核 / 512 MB，以发布截止时间和受管标签回收 |

学生进入开放实验时，只有含编程题的任务会申请容器。运行和同步由 `q_provision` worker 处理。数据库草稿可用于重建工作区文件。每条用例单独启动进程，执行后清理进程和临时文件。预期输出由 worker 比对。学生可查看前两条用例的输入、预期输出、实际输出，其余用例只返回通过状态。

最终运行全通过时提交本题并顺延。编程题全部通过时标记实验完成。选择题在一次提交中判分；报告可在截止前替换附件。三部分各按 100 分展示，补做部分上限为 60 分。补做编程题时保留已通过的题，按补做截止时间创建工作区。

学生接口包括 `/api/v2/tasks/{task_id}/assessment`、`workspace`、题目的 `self-test`、`final-run` 和 `attempts/{run_id}`、`sections/choice/submissions` 及 `report`。教师在发布草稿上传 `report-template`，在评审页下载报告、评分和按部分开放补做。草稿和评分写入使用版本校验，运行和提交使用幂等请求。 [OpenAPI](../../frontend/openapi.json) [前端客户端](../../frontend/packages/api-client/src/assessment.ts)

已有整卷编程提交的学生继续使用其原有答卷和报告评审流程。报告附件继续经过扫描和课程范围授权。演示数据命令可为新发布草稿生成相应的报告模板。验证新增迁移时使用独立测试库，本地容器运行验证需启用 Docker Local 及运行时 worker。

部署升级先应用 Django 迁移并重新运行 MySQL 授权作业，再更新 API、Celery Beat 和运行时 worker。授权清单包含分项补做、报告提交与学生工作区的新增表。

生成契约：从根目录执行 `./scripts/dev/export-openapi.ps1`。同时维护前端共享客户端、类型、查询键与测试。现有 Cookie、CSRF、门户隔离、课程权限、错误包络及审计规则继续适用。
