# 系统架构

> 核对日期：2026-11-04。依据当前源码和 Compose 配置整理。返回[文档索引](../README.md)。

## 系统组成

教学实验平台由学生端、教师端、管理端、Django API、Celery Worker、工作区网关及隔离实验容器组成。

```text
浏览器 → Nginx（门户静态资源与入口）
          ├─ API → Kong → Django → MySQL / Redis / MinIO
          └─ 工作区 → Kong → workspace-gateway → 隔离实验容器
Django → Outbox / Celery → 普通 Worker、运行时 Worker、存储 Worker
运行日志 → Fluent Bit / log-ingest → MongoDB
指标与追踪 → Prometheus / OpenTelemetry Collector
```

本地门户使用 `student.localhost`、`teacher.localhost`、`admin.localhost`；集成 API 使用 `api.localhost`。门户身份由可信代理注入，前端不能自行指定权限。

## 主要业务流程

1. 管理端建立账号资格、运行资源与配额；教师建立课程、成员和教学内容。
2. 教师创建模板版本，配置语言、工程文件、公开数据、测试和 Rubric；附件完成扫描并通过预检后发布。
3. 发布产生个人实验任务，并冻结相应模板和执行配置；学生通过课程与任务权限进入工作台。
4. 运行时服务预留配额并创建实例；学生通过受控会话访问 IDE 和终端。保存、恢复和正式测试经后台任务推进。
5. 正式测试结果与任务、快照及执行配置绑定；符合条件后提交报告或系统成果。教师进行审核，AI 提供建议，最终结果由人工决定。
6. 完成或回收实例时撤销会话，保留相应成果与审计；归档与保留期清理由专用流程处理。

## 服务与权限隔离

- Django Web、普通 Celery 和工作区网关不直接持有本地 Docker Socket。
- Compose 的 `runtime-worker` 处理装载、归档和补偿；`workspace-storage-worker` 独立处理保存恢复队列，继承受控 Docker 访问。
- 工作区网关校验门户会话、工作区令牌、任务归属和 Origin，再访问内部运行时。浏览器不直接接触 Docker API 或上游共享密钥。
- 学生可见数据由后端筛选；隐藏测试、内部命令、对象存储密钥和工具审批信息不能因前端隐藏而视为受保护。
- MySQL 是业务事实源；Redis 和教学分析投影可重建，MongoDB 运行日志不能代替审计事实。
- 业务写入通过服务推进，使用事务、乐观锁及必要的幂等记录；前端状态和 SSE 都不能替代后端授权。
