# 实验工作台-D 测试结果与提交底栏

## 一、目标

将保存、运行测试、测试用例摘要和实验提交统一收纳到工作台底部，同时保持现有任务状态机和报告提交流程不变。

## 二、测试流程

测试按钮调用工作区 gateway：

```text
POST /workspace/{session_id}/operations
operation = RUN_CHECK
→ execution_run_id
→ GET /api/v2/tasks/{task_id}/execution-runs/{execution_id}
```

状态使用现有 `WorkspaceExecutionRunData`：

- `QUEUED`
- `RUNNING`
- `PASSED`
- `FAILED`
- `TIMEOUT`
- `RESOURCE_EXCEEDED`
- `REJECTED`

运行中的测试按钮必须禁用，重复点击不能创建重复执行。

## 三、测试用例信息

底栏只展示公开摘要：

- 测试数量。
- 测试名称或编号。
- 可见输入格式。
- 通过条件摘要。
- 最近一次结果。

不能展示 hidden test 内容、期望值、判题器路径或完整测试资产。

## 四、提交分流

### 报告任务

```text
保存工作区快照
→ 保存报告草稿
→ POST /api/v2/tasks/{task_id}/submit-report
→ 任务进入 UNDER_REVIEW
```

提交按钮应在以下条件不满足时禁用：

- 有未保存工作区内容。
- 报告草稿未保存。
- 附件仍在扫描。
- 当前任务不是 `IN_PROGRESS` 或 `REPORT_DRAFT`。
- 任务存在阻断条件。

### 非报告任务

```text
保存工作区快照
→ POST /api/v2/tasks/{task_id}/complete
→ 任务进入归档/完成流程
```

两条路径都必须使用 `If-Match`、`Idempotency-Key` 和当前任务 `row_version`。

## 五、底栏内容

建议包含：

- 保存状态：已保存、保存中、待同步、版本冲突。
- 工作区版本和客户端序号。
- 最近测试状态和摘要。
- “运行测试”按钮。
- “保存”按钮。
- “提交实验”按钮。
- 检查点、回放和报告入口。

操作反馈必须使用现有 `RequestStateView`、`notice` 和 `form-error` 语义，不通过颜色单独表达失败。

## 六、测试

- RUN_CHECK 能进入执行记录并正确轮询终态。
- 测试超时、资源超限、拒绝和失败都有明确文案。
- 重复点击不会产生重复 execution run。
- 报告任务不会绕过报告草稿直接完成。
- 非报告任务不会进入报告提交流程。
- If-Match 冲突会要求刷新，不覆盖其他版本。
- 提交请求重放返回同一结果。

## 七、完成标准

- 测试和提交都在工作台底栏完成或明确跳转到报告面板。
- 业务状态机仍由后端 service 推进，前端不自行修改任务状态。
- 测试结果不会泄露隐藏检查数据。
- 相关 API、Query key、前端组件测试和 E2E 通过。

## 八、交接产物

交给 实验工作台-E：底栏不会遮挡 Agent 抽屉，测试失败摘要可作为 Agent 上下文。

交给 实验工作台-F：完整的测试、提交和冲突场景。
