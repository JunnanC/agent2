# 实验工作台-F 集成验收与回归门禁

## 一、目标

验证 实验工作台-A 至 实验工作台-E 的组合行为，确保新工作台没有破坏现有实验、保存、测试、提交、Agent 和安全边界。

## 二、用户端完整旅程

至少覆盖：

```text
登录用户端
→ 打开我的实验
→ 开始实验
→ 看到环境加载页
→ 看到真实装载阶段和进度
→ 环境 READY
→ 进入工作台
→ 查看实验内容和模板
→ 切换 WebIDE/Terminal/Preview
→ 自动保存和手动保存
→ 创建检查点
→ 运行测试
→ 查看测试结果
→ 打开 Agent 并完成一次问答
→ 提交报告或完成非报告任务
```

## 三、必须验证的异常

- 环境加载失败且可重试。
- SSE 断开后轮询，恢复后停止轮询。
- 工作区 Session 过期后重新续签或重新进入。
- 自动保存离线排队并恢复同步。
- 快照版本冲突返回明确处理选项。
- 测试执行超时、资源超限和失败。
- 提交时任务被其他请求更新，返回 412。
- Agent 消息异步失败或工具审批过期。
- 任务被撤回、过期或归档后工作区只读/关闭。

## 四、权限和泄露检查

- 学生只能看到自己的任务和当前课程内容。
- 教师不能通过工作台入口获取学生 token。
- 管理端不出现进入学生工作区的能力。
- 浏览器 URL 不出现 workspace token 或签名下载 URL。
- `localStorage` 不包含 Session、Token、Cookie 或敏感报告正文。
- API 错误、日志、SSE 和 Outbox 不包含隐藏测试数据。

## 五、自动化门禁

后端：


```powershell
Set-Location backend/education_experiment_platform
$env:DJANGO_SETTINGS_MODULE = "education_experiment_platform.settings.test"
..\\.venv\\Scripts\\python.exe manage.py check
..\\.venv\\Scripts\\python.exe manage.py makemigrations --check --dry-run
..\\.venv\\Scripts\\python.exe -m pytest
```

前端：

```powershell
Set-Location frontend
npm run typecheck
npm run lint
npx vitest run --pool=threads --maxWorkers=1 --minWorkers=1
npm run build:user
```

集成：

- Compose config 检查。
- OpenAPI 校验和前端生成类型同步。
- 用户端 Playwright 工作台旅程。
- 1440px、920px、390px 无横向溢出。
- 失败时保留 trace、截图和网络日志，但清理 token、Cookie 和签名 URL。
