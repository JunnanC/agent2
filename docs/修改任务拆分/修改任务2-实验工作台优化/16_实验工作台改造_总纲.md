# 实验工作台改造总纲

## 一、目标

将用户端当前的实验工作区改造成接近头歌式的实验工作台：

- 用户进入任务后先看到环境加载页和真实装载进度。
- 环境就绪后进入沉浸式工作台。
- 左侧展示实验内容、实验模板和公开测试说明。
- 右侧展示 WebIDE、Notebook、Terminal、Preview 等工作区能力。
- 底部统一放置保存状态、测试结果、测试和提交操作。
- 右下角提供受控 Agent 悬浮入口。

本阶段优先改造用户端交互和读取契约，不重写 Docker Runtime、workspace-gateway 或 Agent 核心执行器。

## 二、当前基线

现有实现位置：

- 用户端实验详情：`frontend/apps/user-web/src/p06.tsx`
- 用户端工作区：`frontend/apps/user-web/src/p08.tsx`
- 用户端 Agent：`frontend/apps/user-web/src/p12.tsx`
- API 客户端：`frontend/packages/api-client/src/index.ts`
- SSE 客户端：`frontend/packages/event-client/src/index.ts`
- 工作区 API：`backend/apps/workspaces/`
- 运行时装载：`backend/apps/provisioning/`
- 报告提交：`backend/apps/reports/`

已有能力可直接复用：

- `ProvisioningJob` 六阶段装载状态。
- `WorkspaceSession`、快照、检查点和执行记录。
- workspace-gateway 的 `RUN_CHECK` 操作。
- `WorkspaceExecutionRun` 测试执行结果。
- 报告任务的 `submit-report` 和非报告任务的 `complete`。
- `createTaskAgentSession(taskId, "WORKSPACE_ASSIST")`。

## 三、任务拆分

| 编号 | 独立任务 | 主要产物 | 前置任务 |
|---|---|---|---|
| 实验工作台-A | 工作台只读数据契约与内容聚合 | `GET /api/v2/tasks/{id}/workbench`、脱敏 DTO、OpenAPI | 无 |
| 实验工作台-B | 环境加载与工作区生命周期 | 加载状态机、阶段进度、SSE/轮询降级、Session 续签 | 可基于现有接口先行，最终需接入 实验工作台-A 契约 |
| 实验工作台-C | 沉浸式工作台布局 | 左内容/模板、右工作区、响应式和全屏布局 | 实验工作台-A、实验工作台-B |
| 实验工作台-D | 测试、结果与提交底栏 | 测试状态、公开用例、报告/非报告提交分流 | 实验工作台-A、实验工作台-B |
| 实验工作台-E | Agent 悬浮助手 | 圆球、抽屉、任务 Agent 会话、引用和审批 | 实验工作台-B、实验工作台-C |
| 实验工作台-F | 集成验收与回归门禁 | 单元/API/E2E、视口验收、出口记录 | 实验工作台-A 至 实验工作台-E |

实现顺序建议为：工作台数据聚合 → 环境加载 → 工作台布局与测试提交 → 课程助手入口 → 集成验收。实验工作台-C 和 实验工作台-D 可以在 实验工作台-B 完成后并行开发，但必须共享同一个工作台状态模型。

## 四、统一约束

### 4.1 后端写入语义

所有有副作用操作继续遵守：

```text
认证 → Portal/对象范围 → 幂等重放 → 状态检查 → If-Match/CAS
→ 行锁 → 业务写入 → Audit → Outbox → on_commit 异步任务
```

工作台只读接口不得创建 Session、启动运行时或改变任务状态。进入工作区、运行测试、保存快照和提交必须使用显式 mutation。

### 4.2 数据安全

- 不向用户返回 hidden test 输入、期望值、判题器内部路径或完整执行资产。
- 不把 workspace token、Session Cookie、签名 URL 写入 localStorage、日志或 Outbox。
- 模板手册和附件继续通过下载授权接口访问，不直接暴露 MinIO 地址。
- Agent 只能使用当前课程、当前任务和当前工作区范围。
- 教师端只读取工作区投影，不能复用学生工作区 token。

### 4.3 前端状态

- React Query 保存服务端事实；页面本地 state 只保存面板、tab、未提交表单和临时 UI 状态。
- 查询函数不能执行 POST/PUT 等副作用请求。
- SSE 只负责刷新或失效 Query，不直接替代 API 事实。
- SSE 断线时使用短轮询降级，不能用前端计时器推断后端状态成功。
- 工作区 token 只保存在内存和受控 HttpOnly Cookie 机制中。

## 五、统一工作台状态机

```text
ASSIGNED
  └─ 用户点击开始实验
       ↓
PROVISIONING / QUEUED / RUNNING / RETRY
  └─ 环境加载页
       ↓
READY
  └─ 显式创建工作区 Session
       ↓
IN_PROGRESS / REPORT_DRAFT
  └─ 沉浸式工作台
       ├─ 保存快照
       ├─ 运行测试
       ├─ 提交报告
       └─ 完成非报告任务
```

异常分支：

- `FAILED`：显示失败原因、trace 和重试入口。
- `EXPIRED/CANCELLED/COMPLETED`：显示只读结果或归档入口，不签发新的工作区 token。
- `401/403`：清理当前站点 Session，遵循现有门户准入流程。
- `409/412`：显示状态变化或版本冲突，不静默覆盖服务端事实。

## 六、工作台数据契约建议

建议新增用户端只读接口：

```text
GET /api/v2/tasks/{task_id}/workbench
```

返回内容至少包含：

- 任务标题、说明、状态、截止时间、报告策略。
- 实验目标、步骤、约束、交付物等公开内容。
- 模板名称、版本号、依赖、工作区能力、手册/起始文件资产 ID。
- 公开测试数量、规则摘要和当前最近执行结果。
- 装载状态、当前阶段、阶段列表和可计算进度。
- 当前允许操作及阻断原因。

不建议将完整 `execution_spec` 原样返回浏览器；应由后端生成 `test_summary`。

若只读接口不新增数据库字段，则不需要 migration；模板版本、发布快照和任务事实继续作为数据来源。

## 七、统一测试门禁

每个子任务必须覆盖适用的：

- 正常流程。
- 当前用户对象范围。
- Portal 越权。
- 状态冲突和 If-Match 冲突。
- Idempotency-Key 重放。
- 异步处理中、失败、重试和降级。
- 敏感数据不泄露。

最终 实验工作台-F 至少执行：

```powershell
Set-Location backend/education_experiment_platform
$env:DJANGO_SETTINGS_MODULE = "education_experiment_platform.settings.test"
..\\.venv\\Scripts\\python.exe -m pytest

Set-Location frontend
npm run typecheck
npm run lint
npx vitest run --pool=threads --maxWorkers=1 --minWorkers=1
npm run build:user
```

并补充用户端 Playwright 工作台旅程，覆盖 1440px、920px、390px 三种视口。

## 八、非目标

本阶段不做：

- 重写 RuntimeAdapter、Docker Swarm 或 workspace-gateway。
- 新增真实模型供应商或真实工具执行器。
- 把工作区改造成离线应用。
- 把教师端或管理端改造成学生工作台。
- 暴露隐藏测试答案或运行容器内部信息。
- 用前端假进度替代 `ProvisioningStageEvent` 事实。
