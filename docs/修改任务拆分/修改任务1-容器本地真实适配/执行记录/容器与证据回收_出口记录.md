## 结果与问题

```text
正常路径结果：终态归档先撤销 workspace session，再调用 runtime destroy；执行 stdout/stderr/test report 资产写入 retention；judge finally 清理并支持重复删除；过期执行对象和临时 volume 由 retention worker 回收
越权路径结果：只接受 adapter 自己产生的 managed 资源；非 managed 资源不删除；已被 ReportVersion 引用的执行对象不会被 purge
状态冲突结果：CAS/If-Match 冲突保持 P11 语义；补偿任务只更新自身状态，不改写 Review/AutoCheckRun/ReportVersion/ExperimentTask 终态
资源限制结果：TTL 来自冻结 RuntimeSpec；临时资源按 expires_at 回收；judge 仍强制 DENY_ALL，CPU/内存限制仍由运行时 adapter 执行
回收和对账结果：P11 reconcile 继续检查 DB instance、runtime orphan、terminal resource leak、archive object mismatch，并新增 judge/volume transient resource 对账；P11 retention worker 同时处理 archive package、execution object 和过期 volume
日志、trace 和指标结果：失败记录只保留稳定 error_code、异常类型、资源 kind、trace_id；不记录 Docker socket、对象 key 内容、源码或测试正文；P11 reconciliation/retention 指标继续有效
敏感信息泄漏检查：通过静态审查和专项测试；补偿 payload 使用 redact 后的资源 ID/driver/config_ref，不携带连接凭据
已知限制：DOCKER_LOCAL 当前仍是 T04/T07 协议桩；本阶段没有把本地单机 Docker 结果写成真实算法通过，也未宣称 Swarm/HA/生产验收
未解决阻塞：无代码阻塞；真实 DockerLocalAdapter、真实 judge/volume lifecycle、Compose E2E、服务器 Swarm 验收留待 T10/T11；manage.py 数据库门禁需在 Compose MySQL 启动后复跑
```
