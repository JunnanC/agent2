# 实验设计与实验发布使用链路

日期：2026-11-10；对应 `fix/bug-4`。

## 一、两个板块分别做什么

**实验设计**维护可复用的实验模板和版本：章节任务、运行适配器、镜像、资源规格、指导书、报告模板、执行规格与测试。预检通过后发布模板版本，固定本次实验内容。已发布版本不能直接改写；新要求应建立新版本。

**实验发布**把选定的模板版本和评分表版本安排给本课程学生：填写标题、开放/截止时间、分配截止时间和报告要求，创建发布草稿，再点击发布。学生任务从发布生成，学生才会在实验列表和工作台中使用它。仅发布模板不会给学生分配任务。

## 二、完整操作顺序

1. 我的课程 → 新建课程 → 课程概况 → 发布课程。草稿课程不会开放选课。
2. 成员与申请 → 生成并复制邀请码，或审核学生申请。CSV 批量导入是学生名单导入；“学生导入任务”指这次导入的处理进度。
3. 实验设计 → 新建实验模板 → 配置模板：维护内容结构、运行环境、报告材料和执行规格。
4. 运行预检 → 确认阶段通过 → 发布模板版本。已通过或已发布版本复用该次预检，修改内容则建立新的草稿版本。
5. 实验发布 → 新建评分表 → 输入评分项与各项满分 → 创建并发布评分表。权重按满分比例计算。
6. 从实验设计点击“配置发布”，或在实验发布点击“配置新发布”。前者会预选对应模板，二者进入同一发布表单；它不是返回模板编辑器。
7. 选择模板与评分表、填写时间 → 创建发布草稿 → 检查预检状态 → 发布。已通过的模板版本不会再次执行冲突的预检命令。
8. 学生进入实验工作台、执行测试、保存并提交报告 → 教师在报告与评审中评分 → 学生查看结果。

原“验证实验”链接只进入没有后端验证会话的占位页，已从模板列表移除。真实模板可运行性通过预检检查；完整学生流程仍需学生任务与工作台。

## 三、课程材料、章节、日历与问答

- 课程概况新增课程材料维护：先选已发布章节，可创建在线文本、外部链接或选用已上传附件；保存草稿后单独发布。没有章节时，可先创建并发布章节。
- 附件复用实验设计的上传入口：在草稿模板版本上传指导书或报告模板，等待扫描通过；回到课程概况，选择附件所在实验及扫描通过的附件，再发布材料。只开放指导书/报告模板，不开放隐藏测试、隐藏源文件或构建材料。学生在课程介绍查看，并通过一次性下载授权下载。退出课程、撤下材料或章节后不能再申请下载授权。
- 课程章节点击后进入独立地址，可直接刷新访问；仍必须有课程访问权限。课程介绍和章节页面可相互返回。
- 课程日历展示教师设置的课程关键事件，例如实验讲解、答疑、阶段截止；不是每周上课课表。每周排课来自课程排课数据；个人导入只补个人安排。已加入但还没有排课的课程显示“待排课”，不虚构上课时间。
- 课程问答是课程内公开讨论，一条问题可有多条师生回复，不是一对一私聊。成功提交后输入框清空，历史问题保留在独立问答页。

## 四、管理门户数据说明

“资源占用”中的项目是已配置的运行适配器，不可按名称推断实际有几台物理服务器。CPU/内存百分比按配置容量与可用量计算，属于资源容量快照，不等于操作系统实时 CPU 利用率。杭州等名称来自已有适配器记录，不是前端发现了额外服务器。

“健康状态”反映适配器和采集 worker 的检查结果。worker 不可用时保留真实告警，并显示采集错误码、Trace；驱动不可用时展示对应适配器及错误码。应检查 q_provision worker、队列和引擎访问配置，不能靠删除告警判断恢复。

学生管理显示已开设课程对应的教学班，以及有效行政班，再进入该班学生名单。教学班名单直接读取 ACTIVE 选课关系，不复制成员数据。同一学生可属于多个教学班或行政班；同一行政班重复添加保持幂等。行政班多班约束需新增数据库迁移后生效；旧服务曾结束的历史关系不会被自动恢复。
