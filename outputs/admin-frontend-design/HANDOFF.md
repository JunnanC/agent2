# 平台管理端 UI 设计与开发交接

> React UI 已迁移到 `frontend/apps/admin-web`，使用方法见 `frontend/README.md`。此目录的 HTML 保留为设计参考。React 版本仍使用演示数据，尚未接入真实后台。

## 交付范围

- `index.html`：可交互管理端 UI 原型，可直接在浏览器打开。
- 覆盖平台概览、治理待办、运行资源、异常中心、操作审计五个页面。
- 不包含学生端、教师端、正式 React 实现或真实管理操作。
- 页面内统计数字、队列记录和审计记录都是演示数据；不得用于展示或推断真实平台状态。

## 信息架构

| 页面 | 主要任务 | 原型交互 |
| --- | --- | --- |
| 平台概览 | 判断平台健康、优先定位治理事项 | 指标跳转、待办跳转、查看服务健康 |
| 治理待办 | 按优先级发现并分派待处理治理问题 | 关键词搜索、优先级筛选、详情抽屉 |
| 运行资源 | 查看运行时、规格、镜像、实例与会话 | 资源分类切换、关键词搜索、详情抽屉 |
| 异常中心 | 查询任务/扫描/预检异常及补偿 | 状态筛选、对象/Trace 搜索、异常详情 |
| 操作审计 | 按操作者、操作对象、时间和结果追溯变更 | 搜索、结果筛选、演示记录 CSV 导出 |

导航按“总览—治理—运行与审计”分组。Agent 路由、工具策略、成本评估、分析运维暂不放入首批界面，可在确认管理职责和优先级后扩展。

## 页面与 API 参考

正式实现时使用当前门户对应的 `/api/v2` 契约，页面入口按实际权限控制。以下是候选接口分组，具体字段、过滤参数和分页方式以在线 schema、OpenAPI 和后端响应为准。

| 页面/模块 | 候选 API |
| --- | --- |
| 当前管理员及导航权限 | `GET /api/v2/me`、`GET /api/v2/platform/admin-assignments` |
| 治理总览与告警 | `GET /api/v2/platform/governance/alerts`、`GET /api/v2/platform/governance/usage` |
| 课程治理 | `GET /api/v2/platform/courses`、`GET /api/v2/platform/courses/{course_id}`；状态变更前读取详情和允许操作 |
| 镜像治理 | `GET /api/v2/platform/images`、`GET /api/v2/platform/images/{image_id}`；变更或审批以对应 PATCH/POST 契约为准 |
| 资源规格 | `GET /api/v2/platform/resource-profiles` 及单项详情、激活、退役接口 |
| 运行实例 | `GET /api/v2/platform/instances`；销毁前显示服务端约束和确认 |
| 补偿队列 | `GET /api/v2/platform/compensations`；重试使用 `POST /api/v2/platform/compensations` |
| 平台分析 | `GET /api/v2/platform/analytics/quality`、`resource-costs`、`projection-jobs` |
| 事件提示 | `GET /api/v2/events/stream`；事件用于刷新提示，最终状态重新读取 REST 资源 |

异常和审计记录的筛选端点、Trace 关联数据以及平台健康指标，需要开发接入前根据当前后端 schema 核实，不能仅从 UI 原型推断。

## 关键交互与状态

- 页面列表统一具备加载、空数据、错误和重试状态；权限不足应显示无权访问状态，而不是空表。
- 状态颜色配合文字标签；高优先级事项应提供直达对象详情的入口。
- 对会变更平台状态的动作，根据后端 `allowed_actions`、`blockers` 和权限结果渲染；前端按钮显隐不构成授权。
- 更新已有资源时使用响应 `ETag` 与 `If-Match`；收到 `412 ROW_VERSION_CONFLICT` 后保留当前用户输入并提示重新读取/合并。
- 有副作用的命令使用 `Idempotency-Key`；收到 `202` 时持续展示异步任务进度、完成或失败原因。
- API 走门户 Host 的 Cookie session；使用 `credentials: "include"` 与 CSRF 保护，不读取 session cookie、不保存访问凭证。
- Trace ID 作为诊断入口展示；按权限脱敏错误详情，不在日志或 UI 输出密码、令牌、密钥或完整文件内容。
- 破坏性操作（如销毁实例、冻结课程、撤回镜像）必须展示影响对象、确认和后端阻塞原因。

## 视觉与响应式

- 延续静态原型的克制管理台视觉：浅灰绿背景、白色工作区、青绿主色，红/琥珀/蓝分别表达危险、待处理和运行状态。
- 内容优先使用数据表、状态行和清晰分组；统计指标都应链接到可处理的详情/列表。
- 桌面端使用左侧分组导航；窄屏收起导航，数据表允许横向滚动，双栏内容改为单列。
- 交互状态提供键盘焦点、明确标签与文字状态；尊重 `prefers-reduced-motion`。

## 尚待产品确认

1. 首批是否包含用户/教师资格审核、课程冻结与解冻，以及安全策略配置。
2. 异常处理由平台管理员分派，还是管理员直接执行补偿；哪些操作需要二次审批。
3. 审计日志保留时长、导出权限、敏感字段掩码规则和 Trace 可见范围。
4. 平台总览各项指标的数据源、刷新频率、告警阈值和缺数呈现规则。
5. Agent 治理与分析运维是否属于本次 UI 交付。

## 验收标准

- 五个页面均可从管理端导航进入，窄屏布局可用。
- 关键字搜索、状态/优先级筛选、资源分类切换、详情抽屉和演示 CSV 导出可操作。
- 演示数据在界面及交接中明确标识，不被表述为线上数据。
- UI 原型不执行真实平台变更；正式接入须遵守 API、权限、并发和审计约定。
