# 注册邮件容器出站网络缺陷

记录日期：2026-11-06。状态：待在独立分支修复。本文件只记录问题，不包含网络修复。

## 现象

注册接口需要 Django 向 SMTP 服务器发送验证邮件。本地 Docker Compose 中，配置真实 Gmail SMTP 后，`POST /api/v2/auth/register` 返回 503 `EMAIL_SERVICE_UNAVAILABLE`。邮箱中没有收到注册邮件；数据库也没有留下对应正式账号或待注册记录。

## 已确认原因

当前 `docker-compose.dev.yml` 的 Django 仅连接 `app`、`data` 两张 `internal: true` 网络，容器路由表没有默认路由。容器内解析 `smtp.gmail.com` 报 `Temporary failure in name resolution`，直连外部 IP 返回 `Network is unreachable`。临时将 Django 接入可出站网络后，DNS 和 TCP 587 连通，证明原有网络隔离是第一层阻断。

继续测试时，SMTP 连接建立后未收到服务器欢迎响应；Windows 主机也出现过相同的间歇性超时。主机曾成功通过同一组本地凭据发出一封 SMTP 测试邮件并在 Gmail 收到。因此，外网路由修复后仍需在目标环境验证完整 SMTP 会话和邮件投递，不能把 TCP 连接成功当作发信成功。

`infrastructure/swarm/stack.yml` 的 Django 同样只连接内部 `app`、`data` 网络。服务器 CD 使用 `docker-compose.dev.yml` 加服务器专用覆盖文件；该覆盖文件未在本仓库，服务器实际网络尚未核对。

## 后续修复范围

在新的分支中设计 Django 到 SMTP 的出站路径，同时保持业务内部网络隔离。核对 Compose、Swarm 模板和服务器专用覆盖文件的最终网络配置；限制出站目标或在网络侧限制访问范围。不要在当前注册功能分支中混入该网络改造。

验收标准：从实际部署的 Django 容器完成 DNS、SMTP 握手、认证与测试邮件投递；学生和教师注册邮件可送达；验证后权限按注册需求生效。记录目标环境、SMTP 配置方式和测试结果，测试邮箱的待注册记录清理后仍可重新注册。
