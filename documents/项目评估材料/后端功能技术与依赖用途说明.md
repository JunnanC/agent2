# 教学云实验平台功能技术与依赖用途说明

后端开发兼项目经理 配套学习资料

本资料配套两页项目介绍，用于理解当前主链路的技术调用与依赖分工。依据仓库代码、依赖清单和部署配置整理；代码接入不等于线上运行验收，依赖声明也不代表每条业务链路都会调用。

## 当前主链路的技术调用

当前可实现的流程为教师创建模板、发布实验、学生打开实验、准备环境、保存检查点或执行用例测试、教师评阅批改。边界缺陷仍需回归；数据聚合和部分展示仍待联调；Agent 不计入已完成能力。

![实验主链路](D:/all_of_project/edu-agent-platform/documents/项目评估材料/配图/实验主链路.png)

| 功能 | 技术调用与用途 |
| --- | --- |
| 创建实验模板 | React 表单提交；DRF 序列化器校验字段；Django ORM 保存模板、版本、章节与任务；MySQL 持久化。jsonschema 检查自动检查规则的输入与输出 Schema，不是所有表单验证都由它承担。 |
| 按模板发布实验 | Django 校验教师权限和资源依赖；transaction.atomic、select_for_update 与记录版本校验控制并发；固定内容快照并生成学生任务。人数达到配置阈值时，事务提交后交由 Celery 分发。 |
| 学生打开实验 | DRF 校验学生、课程、任务与会话范围；准备状态由前端通过 API 查询。具备工作区入口后，网关校验权限，并通过 httpx 转发适用的 HTTP 请求；不能把点击打开等同于环境已就绪。 |
| 系统准备环境 | Celery 执行耗时准备任务，Redis 提供消息代理及配置中的结果后端；运行时适配器通过 Docker SDK 调用 Engine 创建或检查容器，数据库保存任务与实例状态。真实或桩适配器由配置决定。 |
| 保存快照与检查点 | 代码保存链路校验会话、序号和版本，计算 SHA-256，经 ClamAV 扫描后使用 boto3 写入 MinIO；MySQL 保存资产与快照元数据。检查点关联已有快照，不是 Docker 镜像或整机内存备份。 |
| 执行用例测试 | 请求先绑定任务与代码快照，通过幂等键识别重试；事务提交后由 Celery 调度，运行时适配器调用 Docker 执行测试，记录退出状态与结果。当前执行规范以单文件 Python 入口为边界，不能泛称任意语言在线判题。 |
| 教师评阅批改 | DRF 接收评阅请求，Django 校验权限、待评阅状态、记录版本、自动测试进度和量规评分；事务保存决定并更新任务状态。前端通过 React Query 重新获取相关结果；事件提示不能替代数据库事实。 |

### 技术选择解决的问题

- 事务保证相关数据库更新共同提交或回滚；行锁保护被锁定的记录，版本校验识别过期提交，不能概括为所有并发问题均已解决。
- Celery 负责执行异步任务，Redis 负责消息中转，两者不替代；提交后派发避免 worker 过早读取尚未提交的数据。
- Docker 执行环境、MinIO 文件内容、MySQL 业务记录各司其职；并不是所有数据都放入同一个数据库。
- 幂等键用于识别相同请求重试，不等于系统永远只执行一次；超时、失败重试和跨服务一致性仍需联调与回归。

## 基础设施的职责与使用边界

下列是独立服务、工具或部署方案，与 Python 和 JavaScript 依赖包不是同一层。仓库中存在配置或调用入口，实际启用范围取决于环境；生产集群与高可用能力仍需实机验收。

| 组件 | 本项目职责 |
| --- | --- |
| MySQL | 关系型主业务数据库，保存课程、模板、发布、学生任务、工作区元数据及评阅记录等。 |
| Redis | 消息与短期状态基础设施，提供 Celery broker、配置中的结果后端，以及事件和限流等访问能力。不是关系型主业务数据库。 |
| MongoDB | 运行日志的文档存储与查询；不应概括为平台全部实验业务的数据库。 |
| MinIO | S3 兼容对象存储，保存资料、代码快照与相关结果文件；数据库中保存其引用及元数据。 |
| ClamAV | 上传或快照链路的恶意内容扫描服务；不是漏洞扫描平台，也不是零安全风险保证。 |
| Nginx | 托管三个门户的构建产物，按 Host 区分入口，并按配置进行反向代理。三个前端产物可共用一个 Nginx 镜像。 |
| Kong | API 网关入口，按配置承接接口路由与插件策略；不能替代 Django 的业务权限、状态和数据归属校验。 |
| Fluent Bit | 运行日志采集与转发，配合日志接收服务落库；不是业务统计聚合引擎。 |
| OpenTelemetry Collector | 遥测数据接收、处理与转发组件；配置存在不代表业务埋点和端到端追踪均已完成验证。 |
| Prometheus | 拉取指标并支持查询、告警配置；与应用侧 prometheus-client 配合，不直接替代日志系统。 |
| Docker Engine 与 Dockerfile | Engine 实际管理容器；Dockerfile 描述镜像构建步骤。后端镜像运行 API、worker 等进程，实验容器由运行时适配器管理。 |
| Docker Compose | 本地或单机多服务编排；本项目 p14 profile 联合启动相关服务。单机联调通过不等于集群上线验收。 |
| Docker Swarm | 仓库提供的集群部署方案；需镜像、配置、密钥、网络及真实节点验收，不能表述为已验证高可用。 |
| Docker Context 与 build.context | Docker Context 选择 CLI 连接的 Engine；build.context 指定镜像构建输入目录，两者不同。部署脚本沿用当前 CLI 连接，应结合环境变量核实实际目标。 |

### 阅读时应避免的表述

- 不使用“所有依赖都用于主链路”“Agent 已完成”“平台已稳定上线”等超出当前事实的结论。
- 不把密码哈希说成可解密的加密，不把检查点说成整机备份，不把 boto3 等同于 AWS 部署。
- 不把 Gunicorn 列为当前默认启动方式；当前 Dockerfile 使用 Uvicorn。
- 技术方案解决的是具体问题；任务失败、超时、跨端状态、数据聚合和生产部署仍需分别验证。
