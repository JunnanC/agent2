> 目前项目还在开发和联调阶段，核心链路能够实现，但仍有较多 bug 需要修复，数据聚合和部分统计展示还没有完全打通，Agent 也尚未正式开始开发。接下来，我会优先推动主链路的缺陷修复和回归验证，再推进数据展示和 Agent 等功能。这次角色调整也让我从关注单个页面，转向关注前后端和运行环境之间的完整业务流程。

## 三个技术难点（被追问时补充）

1. **实验状态协同**：实验从发布、环境准备到学生操作，会经过多个状态。我重点关注后端状态和页面展示是否一致，以及重复点击、环境准备失败时该如何反馈，不能只保证正常流程能走通。
2. **环境准备与工作区操作**：环境准备耗时且可能失败，需要通过 Celery 异步处理。检查点和用例测试还涉及学生、任务和工作区的关联。我需要和前端、运维测试同学一起排查问题到底出在接口、任务执行还是运行环境。
3. **教师评阅闭环**：学生完成实验后，教师端要能获取正确的待评阅内容。这里需要统一前后端对权限、状态和字段的理解，不能只验证单个接口返回成功，还要从学生操作到教师批改完整走一遍。

## 部署方式（被追问时补充）

本地通过 Dockerfile 构建后端镜像，由 Docker Compose 编排后端、数据库、Redis、worker 和网关等服务，三套前端统一构建到 Nginx 镜像中。仓库也有 Swarm 部署配置，但正式环境仍需单独验收。Docker Context 用于选择 Docker CLI 连接的引擎，发布前必须确认目标环境，不能把本地运行通过当作生产验收通过。
