# 项目资料索引

> 更新时间：2026-10-27
> 用途：为项目资料提供单一入口，区分目标设计、当前实现、阶段记录、验证证据和历史材料。

## 使用规则

1. 先阅读本索引，再根据任务进入对应目录。
2. “当前实现”以代码、配置和可重复执行的验证脚本为准；设计文档不能单独证明功能已经完成。
3. “阶段出口记录”只说明记录中声明的环境和范围。`本地通过（真实环境待验收）` 不等于生产、HA 或正式部署通过。
4. 本工作区可能存在未提交变更。整理资料时不覆盖这些改动；执行清理、迁移、重建卷等命令前必须先检查 `git status`。
5. 交接与后续安排以 [项目离职交接与后续任务分配部署计划](项目离职交接与后续任务分配部署计划_2026-10-27.md) 为当前工作区核查入口；2026-10-15 的快照和进展说明保留为历史材料，其中前端目录状态等内容可能已过时，必须复查当前代码、`git status`、出口记录和验证脚本。

## 文档状态标签

- **当前入口**：可以直接指导当前工作区操作，但仍需遵守脚本和代码的实际状态。
- **目标设计基线**：描述应达到的架构或契约，不代表所有内容已经实现。
- **本地通过（真实环境待验收）**：已通过记录所述本地门禁，生产/HA/真实外部依赖仍未完成验收。
- **待验收**：存在未完成的环境、证据或回归条件。
- **历史/评估材料**：用于追踪背景、问题和决策，不作为当前实现的直接指令。

## 代码与文档冲突处理

出现冲突时按以下顺序判断：

1. 当前工作树中的代码、配置和迁移是否存在并能被验证。
2. 对应验证脚本是否仍引用这些路径，且命令是否能在当前工作树执行。
3. 最近的阶段出口记录是否明确写出执行环境、范围和未验证项。
4. 目标架构和旧出口记录只用于解释意图，不能覆盖前述事实。

特别注意：2026-10-15 快照记录的 frontend 源码缺失状态已不能直接代表当前工作树。2026-10-27 核查时 `frontend/apps/student-web`、`teacher-web`、`admin-web` 源码均存在；执行构建或部署前仍须以当日 `git status`、实际目录和门禁结果为准。

原阶段任务拆分、P15/P16 改造计划和出口记录中的 `user-web` 或 `frontend/apps/user-web/src/p08.tsx` 等路径，保留的是编写时的实现基线。查阅这些材料时应先对照当前 `student-web` 代码和对应验证结果，不要机械替换历史路径，也不要据此自动恢复、移动或重命名文件。学生端目录名称变化不改变后端门户值 `USER`。

## 维护要求

- 新增阶段或改变接口、部署入口时，同时更新本索引、现状快照和对应 README/设计文档。
- 阶段出口记录必须写明日期、执行环境、验证脚本、通过范围和未验证范围。
- 文档中的文件、脚本、域名和 API 路径不得只凭历史记录保留；每次更新至少用 `Test-Path`、`rg` 或对应验证命令核对一次。
- 不删除历史出口记录；过期内容通过状态、日期和替代入口明确标识。
