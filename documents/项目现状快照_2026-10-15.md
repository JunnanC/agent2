## 三、代码事实（当前工作树）

### 后端应用

`backend/education_experiment_platform/apps/` 当前包含 15 个 Django 应用：

| 领域 | 应用 |
| --- | --- |
| 基础与身份 | `core`、`accounts` |
| 教学业务 | `courses`、`governance`、`labtemplates`、`experiments` |
| 运行时与工作区 | `provisioning`、`workspaces` |
| 成果与治理 | `reports`、`reviews`、`archives` |
| 智能与平台能力 | `agents`、`analytics`、`notifications`、`integrations` |

每个业务应用当前都有自己的模型和 URL 模块；服务层、selector、serializer、view、migration 和测试随应用存放。后端唯一 Django 项目仍是 `backend/education_experiment_platform`，不是文档中曾经出现的平行 `backend/apps` 或根级项目。

### API 与基础设施入口

- `/api/v2/` 由 `backend/education_experiment_platform/education_experiment_platform/urls.py` 挂载。
- API 聚合入口 `backend/education_experiment_platform/education_experiment_platform/api_urls.py` 当前包含上述 15 个应用的 URL，并提供 `health`、`health/ready`、`events/stream` 和 `schema`。
- OpenAPI 在线入口由 `SpectacularAPIView` 提供；导出脚本为 `scripts/export-openapi.ps1`，它会把文件写到 `frontend/openapi.json` 并生成前端类型。该目标文件当前因 `frontend/` 被删除而不存在。
- `settings/base.py` 的运行时模式为 `fake`、`local`、`swarm`。`runtime_adapter_for()` 在 `local` 下直接返回真实 `DockerLocalAdapter`；`runtime_for_driver("DOCKER_LOCAL")` 入口才会按 `LOCAL_RUNTIME_MODE=REAL|STUB` 切换真实适配器与协议替身，不能把两处配置语义混为一谈。`swarm` 使用 `DockerSwarmAdapter`，生产 settings 要求 `RUNTIME_MODE=swarm` 并配置 adapter。
- 本地集成 Compose 实际包含 MySQL、Redis、MongoDB、MinIO、ClamAV、Django、Celery、runtime worker、workspace gateway、Kong、Nginx 和观测服务；这些服务在 `docker-compose.dev.yml` 中定义。
