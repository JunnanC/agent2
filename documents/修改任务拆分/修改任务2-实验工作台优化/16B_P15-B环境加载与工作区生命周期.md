# P15-B 环境加载与工作区生命周期

## 一、目标

将用户进入实验工作台的过程改成真实状态驱动的加载流程，并保证工作区 Session 的创建、续签、撤销和失败恢复可控。

## 二、状态行为

| 任务状态 | 页面行为 |
|---|---|
| `ASSIGNED` | 显示“开始实验”，点击后调用现有 start 接口 |
| `PROVISIONING` 或作业 `QUEUED/RUNNING/RETRY` | 显示环境加载页和阶段进度 |
| `READY` | 显式调用 enter workspace mutation |
| `IN_PROGRESS/REPORT_DRAFT` | 创建或恢复工作区 Session |
| `FAILED` | 显示失败原因和重试入口 |
| `COMPLETED/CANCELLED/EXPIRED` | 禁止签发新 token，进入只读结果或归档页面 |

## 三、进度计算

当前运行时装载阶段为：

```text
QUOTA_CHECK → IMAGE_PREPARE → CREATE → NETWORK_ATTACH → BOOT_PROBE → WORKSPACE_READY
```

进度必须从 `ProvisioningStageEvent` 或装载作业阶段状态计算。建议显示：

- `completed_stages / total_stages`。
- 当前阶段中文名称。
- 阶段失败原因。
- `trace_id`。

没有阶段事实时显示 0% 或“准备中”，不能用前端计时器伪造百分比。

## 四、前端实现原则

重点文件：

- `frontend/apps/user-web/src/p06.tsx`
- `frontend/apps/user-web/src/p08.tsx`
- `frontend/packages/event-client/src/index.ts`

将 `useWorkspace` 拆为只读 Query 和显式 Mutation：

- 查询任务和装载作业只能 GET。
- 进入工作区、创建 Session、续签 Session 使用 mutation。
- mutation 使用稳定的 `RequestIntent`，失败重试不能生成新的业务意图。
- Query 重试不能再次进入工作区或重复创建 Session。

## 五、SSE 与轮询

统一使用 `PortalEventClient` 接收事件并失效 Query。不要只依赖原生 `EventSource.onmessage`，因为后端发送的是带 `event:` 名称的事件。

轮询仅在以下状态启用：

- `QUEUED`
- `RUNNING`
- `RETRY`
- SSE 断线降级期间

工作区 Session 默认 TTL 为 900 秒，建议在 TTL 的 50% 到 70% 时间点续签，并在页面恢复焦点、重新联网和 iframe 重连时补一次校验。

## 六、测试

- 装载六个阶段按真实状态更新进度。
- SSE 断线后轮询，恢复后停止轮询。
- `READY` 进入工作区只创建一个有效 Session。
- Session 过期、撤销、任务终止后不能继续操作。
- 重复点击开始、重试或进入不会产生重复外部作业。
- `409/412/429/503` 均有明确页面状态。

## 七、完成标准

- 加载页面不再把 `PROVISIONING` 当成错误。
- 工作区入口没有副作用 Query function。
- Session 续签和失败恢复可测试。
- user-web 类型检查、组件测试和相关 E2E 通过。
