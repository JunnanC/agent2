# P15-C 沉浸式工作台布局

## 一、目标

把用户端工作区从普通页面改成实验工具布局：左侧实验资料，右侧运行工作区，底部固定操作区。

## 二、页面结构

建议在 `frontend/apps/user-web/src/p08.tsx` 中拆分：

```text
WorkspaceLabPage
├─ WorkbenchHeader
├─ ExperimentContentPane
├─ RuntimeWorkspacePane
├─ WorkbenchFooter
└─ AgentOrb
```

左侧 tab：

- 实验内容。
- 实验模板。
- 测试说明。

右侧 tab：

- WebIDE。
- Notebook。
- Terminal。
- Preview。

右侧工作区仍通过 `WorkspaceSession.workspace_urls` 加载 iframe，不在本任务重写运行时镜像或 gateway。

## 三、布局要求

- 桌面端使用固定左栏 + 弹性右栏。
- iframe 必须有稳定的最小高度，不能因加载文字或按钮变化而跳动。
- 底部操作栏固定在工作区区域底部，不遮挡 iframe 内容。
- 移动端改为上下结构，底部操作栏 sticky。
- 不使用嵌套卡片堆叠；内容区和工作区使用边界、分栏和工具栏表达层级。
- 保持现有 `ui` 包的颜色、按钮、状态和错误组件风格。

## 四、门户布局

若需要隐藏普通门户 footer 或扩大工作区高度，给 `PortalLayout` 增加通用的 `variant="workbench"` 或 `immersive` 属性：

- `frontend/packages/ui/src/components.tsx`
- `frontend/packages/ui/src/styles.css`

该属性只能表达布局，不得把学生业务逻辑放入共享 UI 包。

## 五、内容展示

- 内容使用 P15-A 的安全 DTO。
- 模板资产使用下载授权，不直接访问对象存储。
- Markdown/文本预览必须经过安全处理，不注入不可信 HTML。
- 未加载、空内容、无权限和资产扫描失败均使用统一状态组件。

## 六、测试

- 工作区就绪后能看到左侧内容、模板和右侧能力 tab。
- 未启用的能力不显示或显示不可用状态，不创建 iframe。
- iframe 切换不丢失保存状态和测试结果。
- 1440px、920px、390px 无横向溢出。
- 工作区 token 不出现在页面文本、URL、localStorage 或日志中。

## 七、完成标准

- `p08.tsx` 不再使用“iframe 左侧、操作面板右侧”的旧布局。
- 加载状态、工作区状态、保存状态和执行状态视觉层级清晰。
- 移动端仍能完成保存、测试和提交。
- user-web typecheck、lint、build 和组件测试通过。
